# 주행 기록과 재생

노트북의 기본 저장 위치는 프로젝트 바로 아래의 **주행 데이터**입니다. 회차 폴더 이름에 한국 시각과 고유 ID가 들어갑니다. `manifest.json`에서 운전 모드, 시작·종료 시각, 회차 상태, CAD와 부품 개정, 실행한 소스와 적용 설정을 확인할 수 있습니다.

| 파일 | 무엇을 알 수 있나 |
| --- | --- |
| `events.jsonl` | Nano 명령·응답, 연결·모드 전환, 경로·속도와 정지 사유. 동기화된 자세나 엔코더 입력을 사용한 회차는 `motion_sample`에 원시 CSV 행, 시각과 당시 추정 자세를 함께 기록 |
| `scans.jsonl` | 수집한 회전별 각도·거리·품질, 스캔 시작·끝과 표본 시각의 출처. 거리 0인 무반환 표본도 보존 |
| `sources.zip` | 해당 컴퓨터에서 실행에 사용한 공개 소스 사본. 파일별 SHA-256은 manifest에 기록 |

### 주행하며 수집

- **노트북 수동 조종**은 기존 `python -m vehicle`을 사용합니다. Pi SSH가 가능하면 같은 회차에 라이다를 함께 기록합니다. 기본 대상은 `user@andrea.local`입니다. `--lidar-ssh 사용자@호스트`로 바꿀 수 있습니다. 무인 접속에는 노트북의 기존 SSH 키와 확인된 Pi 호스트 키가 필요합니다. 센서 연결이 끊긴 구간의 사유는 이벤트에서 확인합니다.
- **Pi에서 두 후륜 차량을 기록**하려면 `python3 -m lidar.autopilot --port /dev/ttyUSB0`로 미리보기를 실행합니다. 현재 듀얼 후륜 펌웨어는 Pi의 `LIDAR DRIVE` 명령을 거절합니다. 기존 단일 후륜 펌웨어를 사용하는 차량에만 `--drive`와 실측 인자가 적용됩니다. 통합 콘솔의 `--interactive`는 수동 대기 중에도 같은 USB 연결로 계속 스캔합니다. Pi 프로젝트의 `주행 데이터`에 먼저 저장하므로 노트북 연결이 끊겨도 회차를 보존합니다. [Pi 사용법](../../lidar/autopilot/guide.ko.md)
- **부품 교체** 때는 공용 프로필의 `cad.hardware_revision`과 해당 보정값을 갱신합니다. 특정 회차에만 붙일 때는 `--hardware-rev body-3.5-r2 --change-note "오른쪽 후륜 교체 및 둘레 재측정"`처럼 입력합니다. 센서가 실제로 보고한 카운트, 계산한 목표, Nano ACK는 각각 구분해 해석합니다. 펌웨어가 버전 ID를 제공하지 않으면 회차에는 `unknown`이 남습니다.
- **시각**은 장치별 단조 시각을 사용합니다. Pi USB 스캔과 연결된 센서 자료는 같은 Pi 시간축으로 맞춥니다. 노트북에서 SSH로 수신한 스캔의 수신 시각에는 네트워크 지연이 포함됩니다.

### 노트북으로 수거하고 비교

프로젝트 루트에서 실행합니다. Pi가 별도 폴더에 기록했다면 `sync --remote-root`로 지정합니다. 키 대신 비밀번호로 **수거**하려면 `--ask-password`를 추가합니다.

```powershell
python -m vehicle.drive_data sync user@andrea.local
python -m vehicle.drive_data compare "주행 데이터/첫번째회차" "주행 데이터/두번째회차"
python -m vehicle.drive_data compare "주행 데이터/첫번째회차" --current
python -m lidar.autopilot --session "주행 데이터/첫번째회차" --scan-timing
```

노트북 수동 조종 중에는 시작 시점과 이후 60초 간격으로 닫힌 Pi 회차를 수거합니다. 수동 수거도 같은 파일별 SHA-256을 확인합니다. 로컬에서 편집한 동명 회차와 충돌하면 그 경로를 출력합니다. 강제 종료로 남은 회차는 다음 현지 기록 시작 때 다른 활성 회차와 구별해 `incomplete`로 마감합니다. 노트북에서 수거한 뒤 `manifest.json`의 `state`, `dropped`, `writer_error`를 보면 누락 여부를 확인할 수 있습니다.

두 회차 비교에는 변경된 소스 파일, 설정값, CAD 지문, 부품 개정과 변경 메모가 포함됩니다. `--current`는 기록과 현재 작업본의 공개 소스·하드웨어 프로필을 대조합니다. 실제 부품 교체는 입력한 `--hardware-rev`와 메모로 추적합니다.

### 저장된 센서로 오프라인 재생

`--session`은 회차의 유효한 스캔과 광선 시각을 읽어 현재 계획기를 실행합니다. 같은 회차에 `motion_sample`이 있으면 해당 시각의 저장된 뒷차축 자세를 사용합니다. 이후 후륜 둘레 보정값을 바꿔도 당시 오도메트리로 보정한 스캔을 비교할 수 있습니다. 외부에서 동기화한 다른 자세 또는 카운트를 비교할 때는 `--pose-csv` 또는 `--encoder-csv`를 명시합니다. 자세가 없는 회차에서는 차량이 스캔 중 이동할 수 있는 범위를 고려합니다.

원래 회차와 같은 제어 설정을 비교하려면 `manifest.json`의 `settings`에 기록한 차폭·속도·거리 보정 등을 재생 인자로 지정합니다. 센서 기록으로 계획기를 다시 실행하면 과거 입력에 대한 출력을 확인할 수 있습니다. 새 알고리즘의 조향으로 달렸을 때의 실제 궤적·완주 여부는 별도의 주행 시험에서 확인합니다.
