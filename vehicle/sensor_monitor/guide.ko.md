# GP2Y0A21YK0F 3개 연결과 보정

현재 코드의 센서는 **SHARP GP2Y0A21YK0F 적외선 아날로그 거리 센서 3개**입니다. 측정 범위는 10~80cm, 권장 전원은 4.5~5.5V이며, 출력은 거리에 비례하는 직선 전압이 아닙니다. 변환 주기는 38.3±9.6ms이고 출력 전환 지연도 있습니다. 전원 가까이에 10µF 이상 바이패스 콘덴서를 두도록 제조사가 안내합니다. [SHARP 공식 데이터시트, 3~6쪽](https://global.sharp/products/device/lineup/data/pdf/datasheet/gp2y0a21yk_e.pdf).

## 장착 계획과 변환 설정

현재 차량의 SHARP 거리 센서는 **3개 모두 미장착**입니다. [공용 하드웨어 프로필](../../hardware/control_profile.json)의 `ir_sensors`는 모두 `false`이며, 현재 소스를 빌드한 펌웨어는 ADC를 읽지 않고 세 채널을 `not_connected`로 표시합니다. 장착과 배선을 확인한 채널부터 프로필을 변경하고 Arduino 헤더를 갱신합니다. [부품과 설정](../../hardware/components/ir-sensors.ko.md)

이전 연결 시험에서는 오른쪽 센서 한 개의 Vo를 A2에 직결했습니다. 코드는 직결 시 환산값인 **`dividerRatio=1.0`**을 유지합니다. 당시 A0/A1에 표시된 약 20cm 값은 센서가 연결되지 않은 입력에서 나온 값이었습니다.

Nano 33 IoT 입력은 3.3V용이며 5V tolerant가 아닙니다. 이 설정 변경은 환산 오류를 고치는 것이며 입력 과전압을 보호하는 기능이 아닙니다. 직결 배선의 센서 출력이 근접 물체·전원 변동을 포함해 3.3V를 넘지 않는지는 별도로 확인해야 합니다. [Arduino 공식 Nano 33 IoT 데이터시트, 5쪽](https://docs.arduino.cc/resources/datasheets/ABX00027-datasheet.pdf).

```text
각 센서 Vo ─────────── Nano A0 / A1 / A2
센서 GND ──────────── Nano GND / 전원 GND
```

| 센서 위치 | 센서 단자 | 연결 |
|---|---|---|
| 왼쪽(예정) | Vo | A0, 비활성 |
| 전방(예정) | Vo | A1, 비활성 |
| 오른쪽(예정) | Vo | A2, 비활성. 과거 직결 시험의 분압비는 1.0 |
| 세 센서 각각 | Vcc | 안정화 5V |
| 세 센서 각각 | GND | Nano GND 및 전원 GND와 공통 |

분압비는 `ADC 핀 전압 / 센서 Vo`입니다. 현재 1.0이므로 두 전압은 같습니다. `adcReferenceVolts=3.3`은 명목값이며 실제 보드 기준 전압으로 보정할 수 있습니다. 나중에 각 Vo에 10kΩ 직렬 저항과 ADC–GND 사이 10kΩ 저항을 넣는 분압기로 바꾸면 채널별 `dividerRatio`도 **0.5로 함께 변경**해야 합니다. 배선과 설정을 다르게 두면 거리값이 틀어집니다. 센서 커넥터의 Vo/GND/Vcc는 데이터시트의 보는 방향으로 확인하고, 케이블 색만으로 단자를 확정하지 않습니다. 센서 전원은 Nano 3.3V 핀을 사용하지 않으며 기존 서보 전원의 전압·용량·노이즈 조건도 별도로 확인해야 합니다.

## 입력 처리와 조회

`beginDistanceSensors()`는 12비트 ADC와 A0/A1/A2를 설정합니다. 시작 후 200ms를 기다리고 약 60ms마다 활성 채널을 읽습니다. 채널 전환 후 첫 ADC 변환을 버리고, 다음 5개 ADC 값의 중앙값을 사용합니다. 이는 ADC 순간 잡음을 줄이는 처리이며 센서 자체가 새 거리 측정을 5번 수행했다는 뜻은 아닙니다. 샘플 시간은 ADC 취득 시작 기준이고 센서 내부 변환 지연은 추가됩니다.

`SharpIr.h`의 기본 표는 제조사 곡선에서 대략 읽은 시작값입니다. 보증된 환산식이나 세 센서의 실측 보정값이 아닙니다. 표 사이에서는 역거리 `1/mm`를 보간해 소수 거리값을 얻습니다. 각 센서별로 다른 표를 사용할 수 있습니다.

수정 스케치를 업로드한 후 기존 조종기의 **L** 또는 TCP **`SENSORS`** 명령으로 다음을 조회할 수 있습니다. **2026-11-10에 COM6 업로드와 실제 ADC 응답을 확인했습니다.** 센서별 실제 거리 보정은 아직 하지 않았습니다. 조건과 값은 [개발 기록](../../docs/development-log.ko.md)에 있습니다.

- 원시 12비트 ADC 값, ADC 핀 전압, 적용 분압비, 환산한 센서 Vo, 추정 거리
- `not_connected`, `warming_up`, `in_range`, `far_or_unknown`, `too_near`, `signal_fault`
- 각 측정의 주행 사용 가능 여부 `usable`와 표본 나이

`SENSORS`는 주행 명령을 보내지 않습니다. 기존 접속/종료 시 서보 중앙 동작은 그대로입니다.

## PowerShell 연속 표시

저장소 루트에서 다음 명령을 실행합니다.

프로젝트 폴더에서 실행합니다. 키보드 조종기와 동시에 접속하지 말고 기존 조종기는 Q로 종료합니다.

```powershell
python -u -m vehicle --sensors
```

0.5초마다 LEFT/A0, FRONT/A1, RIGHT/A2의 ADC·ADC 핀 전압·센서 Vo·거리(cm)·상태·사용 가능 여부와 적용 분압비를 출력합니다. 현재 직결 설정이면 `left=1.000, front=1.000, right=1.000`이어야 합니다. 예전 펌웨어가 분압비를 보고하지 않으면 `unknown`으로 표시합니다. 범위 밖이나 오류 상태의 거리는 `--`로 표시하며 포화 800mm를 실측 80cm처럼 표시하지 않습니다. Ctrl+C로 종료합니다. 시작 시 STOP, 종료 시 기존 IDLE을 전송합니다. 주행 명령은 보내지 않으며 기존 접속/종료의 서보 중앙 동작은 적용됩니다.

PowerShell 실행 파일도 제공합니다. 실행 정책으로 차단된다면 위 Python 명령을 사용합니다.

```powershell
.\vehicle\sensor_monitor\monitor-sensors.ps1
.\vehicle\sensor_monitor\monitor-sensors.ps1 -NanoHost 192.168.50.223 -Interval 0.2
```

직접 실행 옵션은 `--host <Nano IP>`, `--sensor-interval 0.2`, `--sensor-duration 5`입니다. 주소는 DHCP에 따라 바뀔 수 있으며 기본은 UDP 자동 검색입니다. `ERR bad command`와 업로드 안내가 나오면 보드에 이전 펌웨어가 실행 중인 것이므로 [현재 스케치](../firmware/PowerOnNano/PowerOnNano.ino)를 USB로 업로드해야 합니다.

## 80cm 밖과 10cm 안의 한계

80cm보다 먼 전방과 지름길 입구를 **정확한 2m 거리**로 반환할 수 없습니다. 낮은 출력은 `far_or_unknown`으로 표시하고 거리 필드에 800mm를 넣지만, 이것은 포화 표시이며 실측 800mm라는 뜻이 아닙니다. 기본 `allowLowSignalAsFar=false`에서는 주행 입력으로 사용하지 않고 정지합니다. ADC 레일 근처 값도 오류로 처리합니다.

이 아날로그 센서만으로 먼 물체·무반사·배선 문제를 모두 구분할 수 없습니다. 특히 10cm보다 가까운 영역은 출력 곡선이 다시 꺾이므로, 일부 근접 물체가 먼 물체처럼 보일 수 있습니다. `too_near`도 높은 전압으로 식별 가능한 경우만 잡으며, 모든 10cm 이내 물체를 감지하는 보장이 아닙니다. 이 한계는 제조사 출력 곡선으로부터 판단한 제어상의 제약입니다. [SHARP 공식 데이터시트, 5쪽](https://global.sharp/products/device/lineup/data/pdf/datasheet/gp2y0a21yk_e.pdf).

따라서 긴 직선에서 사용하려면 실제 벽·빈 공간·근접·전원/배선 오류의 출력을 먼저 확인하고, 센서별 `allowLowSignalAsFar` 정책을 결정해야 합니다. 이를 `true`로 바꾸면 저출력을 포화 800mm로 **가정해서** 진행할 수 있지만, 유효한 원거리 검출이나 고장 판별 기능이 추가되는 것은 아닙니다. 기본 실제 주행 출력도 계속 `kAutonomousActuationEnabled=false`입니다.

## 다음 보정에 필요한 측정

1. 실제 벽을 10, 15, 20, 25, 30, 40, 50, 60, 70, 80cm에 두고 센서마다 ADC/전압을 기록합니다. 특히 주행 목표 거리 근처를 더 촘촘히 기록합니다.
2. `distanceSensorState().calibration[0/1/2]`에 좌/전/우 센서별 표를 지정합니다. 표의 거리는 증가하고 전압은 감소해야 합니다. 표를 간단하게 설정하려면 `beginDistanceSensors()` 끝에서 지정합니다.
3. 좌우 센서 측정면의 차량 중심 오프셋, 전방 센서의 범퍼 대비 위치를 실측합니다. 기존 전방 150mm / 측면 120mm 정지 기준은 임시 값입니다.
4. 실제 속도·정지 거리·차량 크기·최소 회전 반경을 반영한 뒤 주행을 활성화합니다. 센서 데이터만으로 보정되지 않은 회전 반경을 해결할 수는 없습니다.

## 멀티미터 없이 직결 상태를 확인하는 순서

오른쪽 A2를 직결해 시험할 때는 분압비 1.0 설정을 사용합니다. 먼저 센서 전원이 4.5~5.5V 범위의 안정화 전원인지 확인합니다. Nano의 3.3V 전원은 이 센서의 권장 전압보다 낮습니다. Nano의 5V/VUSB 핀도 기본적으로 USB 5V가 항상 출력되는 핀이 아니므로 전원 공급을 가정하지 않습니다. 센서 GND와 Nano GND를 공통 연결하고 제조사 도면의 1=Vo, 2=GND, 3=Vcc를 확인합니다. 커넥터를 바라보는 방향은 제조사 도면과 맞춰야 하며 선 색으로 판단하지 않습니다. [센서 핀·전원](https://global.sharp/products/device/lineup/data/pdf/datasheet/gp2y0a21yk_e.pdf), [Nano 전원·3.3V I/O](https://docs.arduino.cc/resources/datasheets/ABX00027-datasheet.pdf).

흰 종이나 무광의 평평한 벽을 센서 정면 20cm에 고정하고 모니터의 A2 원시 ADC가 반응하는지 확인합니다. 이후 40cm, 60cm에서도 확인합니다. 아래는 현재 임시 변환 표에 해당하는 명목 예시이며 실물 센서 합격 기준이나 보정 완료 값은 아닙니다.

| 실제로 놓을 거리 | 임시 표의 센서 Vo | 직결·명목 3.3V 기준 ADC 예시 |
|---|---|---|
| 20cm | 약 1.30V | 약 1613 |
| 40cm | 약 0.72V | 약 893 |
| 60cm | 약 0.50V | 약 620 |

물체를 멀리할수록 유효 범위에서 전압/ADC가 낮아지는지 먼저 확인합니다. 실제 거리와 비교할 수 있는 값이 모였을 때 변환 표를 보정합니다. 열린 공간에서의 저출력을 임의로 중앙 거리로 맞추거나 ADC 4095 포화를 식의 배율로 숨기지 않습니다. 멀티미터가 없으므로 ADC가 포화되면 실제 입력 전압이 3.3V를 초과했는지는 확인할 수 없습니다.

직결의 입력 한계를 확인하기 어렵거나 정상 입력을 얻지 못해 분압기를 사용할 경우 전원을 모두 끄고 다음처럼 연결합니다. **배선 후 코드도 분압비 0.5로 바꿔 재업로드**해야 합니다. 현재 펌웨어는 1.0이며 아래 회로로 변경된 상태가 아닙니다.

```text
안정화 5V ────────── 센서 Vcc (핀 3)
공통 GND ─────────── 센서 GND (핀 2), Nano GND

센서 Vo (핀 1) ─ 10kΩ ─┬──── Nano A2
                        │
                       10kΩ
                        │
                       GND
```

저항 하나를 직렬로 넣는 것만으로는 1/2 분압이 되지 않습니다. 센서 가까이에 Vcc–GND 사이 10µF 이상 바이패스 콘덴서를 두는 것은 제조사 권장사항입니다. 분압기는 전원 누락·Vo/GND 오배선·센서 고장을 고치는 회로는 아니므로 먼저 전원과 핀 연결을 확인합니다.
