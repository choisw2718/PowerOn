# 거리 센서 3개를 사용하는 벽 중앙 주행 초안

RPLIDAR A1을 사용하는 차량은 [라이다 벽 추종 자율주행 안내](../../lidar/autopilot/guide.ko.md)를 따릅니다.

이 코드는 **SHARP GP2Y0A21YK0F 3개를 사용하는 기본 구현**입니다. **2026-11-10에 펌웨어 업로드와 실제 ADC 응답을 확인했으며**, 모터 구동·자율주행·코너 통과는 시험하지 않았습니다. 기본 설정은 `kAutonomousActuationEnabled=false`이며 실제 센서의 보정과 차량 치수·속도 확인이 남아 있습니다. 기존 수동 조종은 계속 사용할 수 있습니다. [센서 배선·전압 보정·범위 밖 처리](../sensor_monitor/guide.ko.md)를 함께 확인합니다.

현재 차량에는 **IR 거리 센서 3개 모두 미장착**이며 A0/A1/A2를 비활성으로 설정합니다. 오른쪽 A2 ADC 응답과 최대값 포화는 과거 연결 시험 기록입니다. 센서를 장착하고 배선을 확인하면 [장착 플래그와 공용 하드웨어 프로필](../../hardware/components/ir-sensors.ko.md)을 갱신합니다.

## 코드 구성

- [WallFollower.h](../firmware/PowerOnNano/src/ir_wall_following/WallFollower.h): Nano와 PC 테스트가 함께 사용하는 주행 상태 머신과 PD 제어. Arduino나 특정 센서 라이브러리에 의존하지 않습니다.
- [DistanceSensors.h](../firmware/PowerOnNano/src/ir_sensors/DistanceSensors.h): 왼쪽 A0·전방 A1·오른쪽 A2의 12비트 ADC 읽기, 200ms 준비 시간과 60ms 표본 주기, 중앙값 필터 및 센서별 보정 설정.
- [SharpIr.h](../firmware/PowerOnNano/src/ir_sensors/SharpIr.h): GP2Y0A21YK0F의 임시 비선형 변환 표와 센서 상태 구분.
- [AutonomousSteering.h](../firmware/PowerOnNano/src/ir_wall_following/AutonomousSteering.h): 소수 각도 목표를 20ms마다 부드럽게 따라가는 자율 조향 출력.
- [IrAutonomy.cpp](../firmware/PowerOnNano/src/ir_wall_following/IrAutonomy.cpp)는 상태 머신을 후륜 L298N PWM 및 앞바퀴 애커만 조향에 연결합니다. 제어 주기는 명목 20ms이며 거리 기반 PD와 방향 확인은 새 표본에 맞춰 갱신합니다.
- `python -m vehicle`: 기존 수동 조종, 자율주행 시작/상태 명령, CSV 가상 입력 미리보기.
- `vehicle/ir_wall_following/examples/ir_wall_follow_preview.csv`: 직선, 좌우 지름길 입구, 좌·우회전, 앞쪽 장애물 정지의 가상 거리 예제. 차량 운동을 계산한 시뮬레이션이나 실측 로그는 아닙니다.

## 기본 알고리즘

흐름은 `FOLLOW → APPROACH → TURN_LEFT/RIGHT → SETTLE → FOLLOW`입니다. 조건이 위험하거나 판단할 수 없으면 `FAULT`에 머물며 모터 명령을 0으로 만듭니다. 정상 데이터가 돌아와도 자동 재출발하지 않습니다.

1. **직선 중앙 유지:** 양쪽 벽이 보이면 `오차=(왼쪽 중심거리−오른쪽 중심거리)/2`를 사용합니다. 양수면 좌회전, 음수면 우회전입니다. 오차 필터·PD 제어·직선 조향각 제한·조향 변화율 제한을 적용합니다.
2. **지름길 입구 통과:** 전방이 열려 있으면 옆이 열렸다는 이유만으로 회전하지 않습니다. 한쪽 벽이 사라지면 반대쪽 벽을 기준으로 중앙을 유지합니다. 기준 벽이 바뀔 때 미분항을 초기화합니다.
3. **코너 접근:** 전방 600mm 미만이면 낮은 PWM 목표를 사용합니다. 360mm 이하에서는 일단 모터 명령을 0으로 만들고 서로 다른 새 측정 3개로 회전 방향을 확인합니다. 왼쪽/오른쪽 중 정확히 한쪽이 열려 있어야 합니다. 양쪽이 모두 열리거나 닫히면 정지합니다.
4. **회전:** 임시 중심 조향각 ±30°와 회전용 PWM을 사용합니다. 벽을 비스듬히 보는 동안 직선 PD는 적용하지 않습니다. 전방이 열리고, 양쪽 벽의 합이 도로 폭과 맞으며, 중앙 오차와 그 변화율이 안정적인 상태가 새 측정 3개에서 이어지면 새 직선으로 판단합니다. 최소 회전 시간도 확인하며, 최대 회전 시간을 넘으면 정지합니다.
5. **정렬:** 직선 PD로 복귀하면서 조향을 빠르게 풀고 잠시 낮은 PWM을 유지합니다. 큰 회전각이 남아 있으면 직선 속도로 복귀하지 않습니다.

자율주행은 키보드의 2° 단계를 사용하지 않습니다. 소수 각도를 유지한 뒤 기존 `writeMicroseconds()`에서만 1µs 정수 펄스로 반올림합니다. 현재 명목 보정 10µs/° 기준 바퀴 각도 약 0.1°의 **명령 분해능**이며 실제 서보의 기계적 정밀도를 보증하지 않습니다. 기존 코드도 1µs 출력을 사용했고, 이번 변경은 50Hz 출력 보간과 직선 20°/s 변화율로 급격한 조향을 줄입니다. 회전 진입·정렬은 별도 90°/s로 처리합니다. 회전 진입 시 명령 각도가 준비될 때까지 모터 명령을 0으로 유지하지만, 실제 서보 위치를 측정하는 기능은 아닙니다.

센서의 원시 거리에 차량 중심부터 센서 측정면까지의 좌우 오프셋을 더해 **중심거리**를 구합니다. 도로 폭 610mm, 좌우 센서 오프셋 각 100mm라면 원시 목표 거리는 각 205mm입니다. 좌우 오프셋이 서로 달라도 보정할 수 있습니다. 이 오프셋은 차량 폭의 절반으로 임의 대체하지 말고 센서 위치를 실측합니다.

## 미정인 값과 현재 임시 설정

[IrAutonomy.h](../firmware/PowerOnNano/src/ir_wall_following/IrAutonomy.h)의 `makeWallFollowConfig()`에서 [WallFollower.h](../firmware/PowerOnNano/src/ir_wall_following/WallFollower.h)의 기본값을 덮어쓸 수 있습니다.

| 항목 | 임시 값 / 의미 |
|---|---|
| 도로 폭 | 610mm, 첨부 트랙 안내 기준 |
| 센서 거리 범위 | 100~800mm; 예제 CSV도 이 범위 사용 |
| 좌우 센서 오프셋 | 각 0mm; 가상 예제용이며 실제 장착값 아님 |
| 벽으로 사용하는 최대 중심거리 | 480mm 미만 |
| 회전 방향이 열렸다고 판단하는 중심거리 | 650mm 이상 |
| 양쪽 중심거리 합의 도로 폭 허용 오차 | ±120mm |
| 접근 / 회전 확인 시작 전방 거리 | 600 / 360mm |
| 회전 후 전방 열림 거리 | 700mm 이상 |
| 긴급 정지 원시 거리 | 전방 150mm 이하, 좌우 120mm 이하 |
| 직선 / 접근 / 회전 PWM | 60 / 58 / 58% |
| 직선 최대 조향 / 회전 조향 | ±18° / ±30° 중심각 |
| 조향 갱신 / 직선·회전정렬 변화율 | 20ms / 20°/s·90°/s |
| P / D 이득 | 0.08°/mm / 0.025°/(mm/s) |
| 측정 유효기간 | 300ms; 실제 정지는 다음 제어 틱과 통신 처리 지연도 포함 |
| 최소 / 최대 회전 시간 | 400 / 4500ms |
| 회전 종료 조건 | 중앙 오차 ≤100mm, 변화율 ≤150mm/s, 통로 폭 일치, 3회 확인 |
| 회전 후 낮은 PWM 유지 | 500ms |

PWM은 속도 피드백이 아닙니다. 58~60%가 실제로 저속인지, 바퀴가 기동하는지조차 아직 확인하지 않았습니다. 기존 수동 `DRIVE`의 명목 7V 최소 보정 대신, 자율주행은 PWM을 직접 지정합니다. 실제 속도·정지 거리·차량 길이·센서에서 범퍼까지 거리·최소 회전 반경에 따라 전방 임계값과 회전 조향/PWM을 함께 조정해야 합니다. 모터 정지는 기존 L298N ENA 비활성 방식으로, 제동 거리가 0이라는 뜻이 아닙니다.

## 센서 없이 PC에서 확인

아래 명령은 저장소 루트에서 실행합니다.

프로젝트 폴더에서 다음 명령을 실행합니다. 호스트 C++ 컴파일러 `g++`가 필요하며, 이 PC에서는 설치된 CodeBlocks MinGW를 자동으로 찾습니다. Python은 표준 라이브러리만 사용합니다.

```powershell
python tests/run_all.py
```

실제 Nano에 들어가는 C++ 제어기를 PC용으로 빌드하고, 가상 시나리오 및 Python 입력/재생 검사를 수행합니다. 끝에 예제 CSV를 읽고 `FOLLOW`, `APPROACH`, `TURN_LEFT`, `SETTLE`, `TURN_RIGHT`, `FAULT` 전환을 출력합니다. 보드 연결이나 모터·서보 명령은 전송하지 않습니다.

## Nano에서 가상 거리 미리보기

현재 스케치가 업로드된 보드에서 다음을 실행하면 CSV 데이터를 20Hz로 보내 Nano의 계산 목표를 확인할 수 있습니다. 실제 보드에서의 이 CSV 재생 시험은 아직 수행하지 않았습니다.

```powershell
python -m vehicle --preview-csv vehicle/ir_wall_following/examples/ir_wall_follow_preview.csv
```

자동 검색이 되지 않으면 `--host <현재 Nano IP>`를 추가합니다. 프로그램은 `STOP`, 가상 `RANGES`, `AUTO TEST`, `AUTO STATUS`를 보내며 실제 주행 시작 명령은 보내지 않습니다. `AUTO TEST`는 계산만 하고 모터·서보에 목표를 적용하지 않습니다. **기존 펌웨어 동작인 접속 시 및 종료 `IDLE`의 서보 중앙 명령은 그대로 적용됩니다.** 모터 전원을 분리한 상태에서 확인합니다. Ctrl+C로 중단할 수 있습니다.

TCP 명령은 아래와 같습니다. `RANGES`를 먼저 보낸 후 유효기간 내 `AUTO TEST`를 보내고 계속 새 거리를 공급해야 하므로 수동 타이핑보다 위 CSV 재생을 사용합니다.

| 명령 | 동작 |
|---|---|
| `RANGES <left_mm> <front_mm> <right_mm>` | 가상 입력만 갱신. `-1`은 센서 오류를 나타냄 |
| `AUTO TEST` | 최근 가상 입력으로 계산 모드 시작 |
| `AUTO STATUS` | 모드, 상태, 오류, PWM/조향 목표, 중앙 오차, 기준 벽, 회전 완료 수 출력 |
| `AUTO START` | 실제 센서 입력으로 주행 시작. 기본 빌드에서는 거부 |
| `AUTO STOP` / `STOP` | 자율주행 취소와 모터 정지 |
| `IDLE` | 자율주행 취소, 모터 정지, 서보 중앙 |

`wall_ref=1/2/3`은 왼쪽/오른쪽/양쪽 벽입니다. `duty_target`과 `steer_target`은 계산 결과이며 `steer_smoothed`는 보간한 명령입니다. 실제 모터·서보 명령은 기존 `STATUS`의 `duty_cmd`, `enabled`, `steer_center`와 구분합니다. 회전 중 `error_mm`는 마지막 직선 제어 때의 값입니다. `turns`는 회전 종료 판정 횟수이며 위치·바퀴수·완주 판정이 아닙니다.

기존 조종기의 **`1`(또는 G)**은 `AUTO START`, **`0` 또는 `-`**는 `IDLE`을 보내 자율주행을 취소하고 모터 정지·조향 중앙 후 수동으로 복귀합니다. 전환 시 Python의 수동 속도·조향 기억값도 0으로 초기화합니다. `B`는 `AUTO STATUS`입니다. 수동 구동/조향 명령은 자율주행을 취소하고 제어권을 가져옵니다. TCP·Wi-Fi 연결 해제도 자율주행을 취소하고 정지합니다. 수동 모드의 기존 마지막 명령 유지 동작은 그대로입니다. 이 키들은 일반 `python -m vehicle` 실행에서 사용하며 `--sensors` 모니터는 조회 전용입니다. 실제 시작에는 기존 펌웨어 활성화 설정과 정상 센서 입력이 필요합니다.

## 실제 센서를 연결할 때

1. [배선 안내](../sensor_monitor/guide.ko.md)를 따라 센서 전원과 Nano ADC의 3.3V 입력 한계를 확인합니다. 장착·배선을 확인한 채널을 프로필에서 활성화하고 `SENSORS`/조종기 `L`로 ADC 핀 전압·적용 분압비·센서 Vo·상태를 확인합니다. 분압기를 추가하면 설정도 함께 변경합니다. 좌우는 측면, 전방은 정면을 향하고 측정면은 200mm 벽을 읽는 높이라고 가정합니다.
2. 기본 변환 표를 실제 센서별 표로 보정합니다. ADC는 60ms마다 새로 읽으며 오류도 새 invalid 표본으로 전달합니다. 센서 내부 지연을 포함해 정지 거리를 측정해야 합니다.
3. GP2Y0A21YK0F는 범위 밖 공간과 일부 이상 상태를 구분하지 못합니다. 낮은 출력은 기본적으로 `far_or_unknown`, 주행 불가입니다. 긴 직선을 달릴 때 필요한 `allowLowSignalAsFar` 정책은 실물 검토 후 명시적으로 설정하며, 이를 켜도 오류 검출이 보장되는 것은 아닙니다.
4. 센서 오프셋, 차량 크기·회전 반경, 실제 속도·정지 거리를 반영합니다. 회전 조향각은 기존 아커만/서보 한계 내에서 사용합니다.
5. 설정 검토 후 `kAutonomousActuationEnabled=true`인 빌드에서만 `AUTO START`가 허용됩니다. 이 경우에도 신선하고 유효한 실제 센서 입력이 없으면 출발하지 않습니다. 가상 `RANGES`는 실제 주행 입력으로 사용하지 않습니다.

이 초안은 반응형 통로 추종입니다. P01~P20 위치 추정, 회전 순서 지도, 출발/도착 인식, 한 바퀴 후 정지는 구현하지 않았습니다. 지름길 입구에서 전방이 열리고 반대쪽 벽이 남는다는 조건에서는 직진하지만, 두 벽이 동시에 사라지거나 전방까지 막힌 분기·장애물은 정지합니다. 세 센서만으로 회전각이나 절대 자세를 직접 측정할 수 없으므로 코너 종료 조건은 실물에서 보정해야 하며, 첨부 트랙 완주를 보장하는 검증 결과는 아직 없습니다.
