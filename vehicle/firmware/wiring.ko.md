# Nano 33 IoT 차량 배선과 조향 보정

듀얼 후륜이 현재 기본 모드입니다. [JGA25-370 모터·엔코더 배선](dual-rear.ko.md)을 사용하세요. 아래 모터 핀은 중앙 후륜 모드 복귀용이며, 조향 보정은 두 모드에서 공통입니다.

## 중앙 후륜 모드 배선

배선을 바꿀 때는 전원을 모두 끕니다. Nano 보드에 인쇄된 D핀 이름을 기준으로 연결합니다.

| Nano / 장치 | 연결할 곳 |
|---|---|
| Nano D9 | L298N **ENA 신호핀**; ENA–5V 점퍼 제거 |
| Nano D2 | L298N IN1 |
| Nano D4 | L298N IN2 |
| Nano D3 | 미연결 |
| 모터 두 선 | L298N OUT1 / OUT2 |
| Nano D5 | 기존 L 서보 신호선 |
| Nano D6 | 기존 R 서보 신호선 |
| Nano A0 / A1 / A2 | 왼쪽 / 전방 / 오른쪽 SHARP 센서 장착 계획. 현재 3개 모두 미장착·비활성. [IR 장착 상태와 배선](../../hardware/components/ir-sensors.ko.md) |
| Nano GND | L298N GND와 서보 전원 마이너스에 공통 연결 |
| Nano 전원 | USB |
| 서보 전원 | 서보 정격에 맞는 별도 안정화 전원; 기존 설정은 5 V |

ENA의 두 핀 중 **신호핀과 5 V 점퍼 핀을 구분**합니다. D9를 5 V 핀에 연결하지 않습니다. ENB도 5 V 점퍼 핀을 GND에 연결하면 단락이 생기므로 신호핀을 확인해야 합니다.

2026-10-05 사용자 기록에는 L298N `12V–GND=12 V`, `5V–GND=0 V`가 있습니다. 모터 전원 외에 **로직 약 5 V가 실제로 공급되는지** 확인해야 합니다. 모듈의 레귤레이터/전원 점퍼 구성은 아직 확인되지 않았으므로 외부 5 V와 내부 레귤레이터 출력을 임의로 함께 연결하지 않습니다. Nano D핀은 3.3 V 신호용이며 5 V를 입력하지 않습니다. [L298 데이터시트](https://www.st.com/resource/en/datasheet/l298.pdf), [Nano 33 IoT 데이터시트](https://docs.arduino.cc/resources/datasheets/ABX00027-datasheet.pdf).

## 조향 중립 보정

2026-10-08 사용자가 1차 보정 스케치를 업로드한 뒤 확인한 정렬 위치와 두 서보의 거울 대칭 배치를 반영했습니다. 기존 교차 설정인 **D5=물리적 오른쪽, D6=물리적 왼쪽**을 유지하는 가정입니다. 실제 연결은 아직 재확인하지 않았습니다.

| 물리적 바퀴 (현재 가정) | 1차 보정 후 정렬된 명령 | 2차 중앙 펄스 |
|---|---|---|
| 오른쪽 | `DRIVE 0.0 26.0` | D5: 1597 µs |
| 왼쪽 | `DRIVE 0.0 -30.0` | D6: 1416 µs |

1차 펌웨어의 바퀴별 각도 계산에서 각 바퀴가 정렬된 채널의 펄스를 선택했습니다. 사용자는 2차 보정 후 중립이 잘 맞는다고 확인했습니다. 이후 요청에 따라 중립은 유지하고 **왼쪽 D6의 방향만 -1→+1**로 바꿨습니다. 현재 방향은 **D5=+1 / D6=+1**입니다. `+26`이나 `-30`을 각도 오프셋으로 다시 더하지 않습니다. 수정된 스케치를 업로드하고 조종기를 새로 연결한 뒤, 모터 전원을 분리한 상태에서 `I`로 정지+중앙을 적용하고 `R`로 아래 예상 상태를 확인합니다.

```text
steer_center=0.0deg servo_us_l=1597 servo_us_r=1416
steering_cal=ackermann-body2-v4 neutral_us_d5=1597 neutral_us_d6=1416 direction_d5=1 direction_d6=1 channels_crossed=1
```

`servo_us_l/r`은 물리적 좌우가 아닌 D5/D6 채널을 뜻합니다. `pulse_limit_d5/d6=1`이면 해당 펄스가 설정 상하한에 걸린 상태입니다. 1차 펌웨어에서 +26°의 D6는 1952 µs 상한에 걸렸으며 그 출력은 오른쪽 정렬의 중립값으로 사용하지 않았습니다.

기존 펄스 상하한은 유지했습니다. 중립 성공은 사용자 보고로 확인했고, 이번 왼쪽 방향 변경 후 `A/D` 한 번씩의 작은 좌·우 동작은 실물에서 재확인해야 합니다. D5/D6의 실제 바퀴 대응이 위 가정과 다르면 먼저 해당 채널을 확인합니다. 반대 매핑에서는 D6 중립 샘플이 상한에 걸리므로 코드가 컴파일을 거부하게 했습니다.

## 도면 기반 애커만 조향

현재 스케치는 `body-2` 도면과 확인된 HS-311 모델을 사용해 조향을 계산합니다. 중립 펄스와 방향은 위 보정값을 유지합니다. 후륜 축이 도면 중앙 구멍의 중앙에 있고 두 서보 출력축이 바깥쪽을 향하는 배치, 막대가 바퀴 축과 나란하고 전후 오프셋이 없는 구조를 가정한 명목값 **축간거리 133.24 mm / 서보축 간격 121.20 mm**입니다. 치수 산출과 남은 확인 항목은 [개발 현황](../../docs/development-log.ko.md)에 기록했습니다. 업로드·실물 slip 개선은 아직 확인하지 않았습니다.

조종기 `steer` 값은 가상의 중앙 바퀴 각도이며 실제 앞바퀴 두 개에 같은 각도를 보내지 않습니다. 좌회전에서는 왼쪽, 우회전에서는 오른쪽이 더 크게 꺾입니다.

| 중심 명령 | 왼쪽 목표 | 오른쪽 목표 | D5 / D6 예상 펄스 |
|---|---|---|---|
| 0° | 0° | 0° | 1597 / 1416 µs |
| +10° | +10.85° | +9.27° | 1690 / 1525 µs |
| +20° | +23.57° | +17.34° | 1770 / 1652 µs |
| +30° | +38.06° | +24.57° | 1843 / 1797 µs |
| -30° | -24.57° | -38.06° | 1216 / 1170 µs |

`R`로 보는 `wheel_left_deg/right_deg`는 물리적 좌우 바퀴의 **계산 목표**이며 센서 측정값이 아닙니다. `steer_requested`와 `steer_center`는 요청/적용 중심 각도, `steer_limited=1`은 두 바퀴의 공통 회전 반경을 유지하도록 명령을 제한했다는 뜻입니다. 현재 계산 범위는 약 -34.50°~+39.99°이고 키보드 범위는 ±30°입니다. `geometry=body2-hs311-nominal wheelbase_mm=133.24 pivot_track_mm=121.20`으로 새 설정을 확인할 수 있습니다.

업로드 후에는 모터를 정지한 상태에서 중앙과 작은 각도부터 확인하고, +10/+20/+30° 및 반대 방향에서 실제 바퀴 방향이 위 목표에 맞는지 비교합니다. 계속 끌리면 실제 축 위치와 바퀴 각도를 측정해 채널 대응·각도당 펄스를 보정해야 합니다. 중립 정렬만으로 큰 각도의 정확성까지 확인되지는 않습니다.
