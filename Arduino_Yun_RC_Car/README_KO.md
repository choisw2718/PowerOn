# Arduino Uno R3 PowerOn 직접 제어

이 폴더의 스케치는 **클래식 Arduino Uno R3(ATmega328P, 16 MHz)**가 두 후륜 모터, 두 전륜 조향 서보, 두 quadrature 엔코더를 직접 제어하도록 구성되어 있다. 폴더 이름에는 이전 작업의 `Yun` 명칭이 남아 있지만 현재 코드는 Yún, Uno R4, ESP32용이 아니다.

현재 좌우 후륜 모터는 모두 **RB-35GM 09TYPE DC 24V W/EC 26P**로 교체되었다. 실제 감속비, 회전당 카운트와 PID가 아직 확정되지 않았으므로 속도 기반 주행은 잠겨 있으며, 원시 `@MOTOR` 벤치 시험은 최대 10%로 제한된다.

> 중요: Arduino와 NUCLEO를 같은 모터 드라이버 또는 서보 신호선에 동시에 연결하지 않는다. 제어 보드는 하나만 사용한다.

## 1. 필요한 항목

- Arduino Uno R3 또는 호환 ATmega328P 16 MHz 보드
- Arduino IDE의 `Arduino AVR Boards` 코어
- USB 시리얼 연결
- 추가 Arduino 라이브러리 없음

Yún의 Bridge/Linux 웹 기능은 제거했다. 일반 Uno R3에는 네트워크 기능이 없으므로 이 구현은 USB 시리얼로 제어한다.

## 2. Uno 핀 연결

| 기능 | Uno 핀 | 연결 대상 |
|---|---:|---|
| 서보 출력 채널 L | D5 | 교차 하네스의 실차 우측 HS-311 신호선 |
| 서보 출력 채널 R | D6 | 교차 하네스의 실차 좌측 HS-311 신호선 |
| 좌측 모터 PWM | D9 | 드라이버 L_PWM |
| 좌측 모터 IN1 | D2 | 드라이버 L_IN1 |
| 좌측 모터 IN2 | D4 | 드라이버 L_IN2 |
| 좌측 모터 ENABLE | D3 | 드라이버 L_ENABLE |
| 우측 모터 PWM | D10 | 드라이버 R_PWM(6번) |
| 우측 모터 IN1 | D7 | 드라이버 R_IN1(4번) |
| 우측 모터 IN2 | D8 | 드라이버 R_IN2(7번) |
| 우측 모터 ENABLE | D11 | 드라이버 R_ENABLE(8번) |
| 좌측 엔코더 A/B | A0 / A1 | 좌측 엔코더 A/B |
| 우측 엔코더 A/B | A2 / A3 | 우측 엔코더 A/B |

- D0/D1은 USB 시리얼 업로드와 제어에 사용하므로 다른 장치에 연결하지 않는다.
- A4/A5와 D12/D13은 현재 비워 두었다.
- 설정과 배선을 함께 바꿔야 한다. 스케치의 인터럽트 코드는 위 엔코더 배치를 전제로 한다.
- 현재 조향 하네스는 출력 채널 이름과 물리 바퀴가 좌우 교차되어 있다. 펌웨어는 `POWERON_SERVO_CHANNELS_CROSSED=1`로 이를 보정하므로 D5/D6을 서로 바꾸면 이 값도 반드시 0으로 바꾼다.

## 3. 모터 드라이버와 전원

대상 드라이버는 **M.A.I DC MOTOR DRIVER V3.0(MAI-2MT-DC)**이다.

- 각 채널의 IN1과 IN2는 항상 서로 반대 상태로 구동한다.
- ENABLE은 **Low-active**다. 정지 상태에서는 ENABLE=HIGH, PWM=LOW, IN1=IN2=LOW다.
- 방향을 바꿀 때는 ENABLE과 PWM을 먼저 끄고 50 ms 기다린 뒤 다시 구동한다.
- 모터 전원 24 V는 드라이버의 MOTOR VCC에만 연결한다.
- 드라이버 로직 전원은 제품 조건에 맞는 4.5~6 V를 사용한다.
- HS-311 두 개는 별도 4.8~6.0 V 전원을 사용한다. 합산 스톨 전류 1.6 A보다 여유 있는 전원이 필요하다.
- Uno, 드라이버, 엔코더, 서보 전원의 GND는 반드시 공통으로 연결한다.
- 모터나 서보를 Uno의 GPIO 또는 5 V 핀에서 직접 구동하지 않는다.
- L298N 계열 드라이버의 전류와 발열이 실제 모터의 기동·정지 전류를 감당하는지 확인한다.

Uno는 5 V 로직 보드이므로 0~5 V 엔코더 신호를 받을 수 있다. 엔코더 출력이 open-collector라면 스케치의 내부 풀업이 사용되지만, 긴 배선이나 노이즈가 있으면 적절한 외부 풀업과 신호 정형을 권장한다. 5 V보다 높은 신호는 절대 직접 입력하지 않는다.

새 모터의 실제 여섯 배선 색상은 **보라색 (Purple), 파란색 (Blue), 민트색 (Mint), 갈색 (Brown), 빨간색 (Red), 검은색 (Black)**이다. Motor terminal 1/2와 Encoder VCC/GND/A/B의 색상별 대응은 모두 `TBD`이므로 데이터시트 또는 측정으로 확인하기 전에는 어느 선도 24 V나 Uno 핀에 연결하지 않는다.

## 4. 타이머 배치

- Timer0: Arduino의 `millis()`, `delay()` 유지
- Timer1: D9/D10의 좌우 모터 PWM, 20 kHz
- Timer2: D5/D6의 두 조향 서보 펄스, 약 50 Hz(한 프레임 안에서 채널별 순차 출력)

표준 `Servo` 라이브러리는 Timer1을 점유하므로 사용하지 않는다. 이 스케치는 Timer2 인터럽트로 두 서보 펄스를 직접 만든다. 좌우 펄스는 20 ms 프레임 안에서 순차로 출력되며, 각 채널의 중립·보정 펄스 폭은 서로 독립적으로 유지된다. 타이머 해상도는 4 us이므로 설정값은 가장 가까운 4 us 단위로 반올림되며 `@STATUS`에는 반올림된 실제 펄스 폭이 표시된다. `tone()`이나 Timer1/Timer2를 사용하는 다른 라이브러리를 함께 추가하면 충돌할 수 있다.

## 5. 업로드

1. Arduino IDE에서 `Arduino AVR Boards`를 설치한다.
2. `Arduino_Yun_RC_Car.ino`를 연다.
3. 보드에서 **Arduino Uno**를 선택한다.
4. Uno의 USB 포트를 선택하고 업로드한다.
5. 시리얼 모니터를 `115200 baud`, 새 줄 전송으로 연다.

## 6. 명령

```text
@DRIVE 0.20 10
@SPEED 0.10
@STEER -10
@CENTER
@STOP
@IDLE
@STATUS
@MOTOR 10 10
@SERVO 1398 1402
@TIMEOUT 1500
@HELP
```

접두사 없이 `w/s/a/d/c/z/x/i/h` 한 글자도 사용할 수 있다. 키 입력을 즉시 전송하는 시리얼 터미널에서는 방향키도 동일하게 사용할 수 있다. 펼웨어는 ANSI `ESC [ A/B/C/D`, `ESC O A/B/C/D`와 Windows 확장 방향키 코드를 인식한다.

> 현재 `POWERON_CLOSED_LOOP_READY=0`이다. 0이 아닌 `@DRIVE`/`@SPEED`와 W/S는 오류로 거부된다. 감속비·실측 엔코더 카운트·A/B 부호·전압·PID를 확인한 뒤에만 잠금을 해제한다. `@MOTOR`는 요청값이 더 크더라도 10%로 제한된다.

| 키 | 동작 |
|---|---|
| W / S | 목표 속도 ±0.05 m/s |
| A / D | 조향 ±1° |
| ↑ / ↓ | W / S와 동일 |
| ← / → | A / D와 동일, 조향 ±1° |
| C | 조향 중앙 |
| Z | 목표 속도 0 |
| X 또는 Space | 모터 즉시 정지, 조향 유지 |
| I | 모터 정지 후 조향 중앙 |
| H | 도움말 |

조향 명령은 가상 중심 바퀴의 각도이며, 음수는 우회전, 양수는 좌회전이다. A/D는 1°씩 조절하고, `@STEER 0.5`처럼 소수 각도도 명령할 수 있다. 실제 서보 출력은 4 us 타이머 해상도와 10 us/deg 변환값에 따라 약 0.4° 단위로 반올림된다. 개별 바퀴의 기구 한계 `-45°~+55°`와 현재 축거·전륜 윤거를 Ackermann 식에 적용한 안전 중심 명령 범위는 약 `-34.83°~+41.32°`이다. 범위를 넘는 명령은 자동 제한된다.

Arduino IDE 시리얼 모니터는 방향키를 즉시 전송하지 않는다. Windows에서는 보드의 COM 포트를 확인한 뒤 이 폴더에서 다음과 같이 실행하면 방향키와 WASD를 바로 사용할 수 있다.

```powershell
powershell -ExecutionPolicy Bypass -File .\keyboard_control.ps1 -Port COM3
```

`Q`나 Esc로 종료하면 도구가 `i` 명령을 보내 모터를 정지하고 조향을 중앙으로 복귀한 뒤 포트를 닫는다.

모터가 움직이는 동안 1.5초간 새 명령이 없으면 ENABLE과 PWM이 자동으로 꺼진다. `@TIMEOUT 3000`처럼 변경할 수 있지만 실제 주행에서는 `@TIMEOUT 0`으로 안전 정지를 해제하지 않는다.

`@STATUS`의 주요 항목은 다음과 같다.

- `target_mps`: 사용자가 요청한 차량 중심 속도
- `applied_mps`: 조향 중 바깥 바퀴가 0.60 m/s를 넘지 않도록 제한된 실제 중심 목표
- `steer_deg`, `turn_radius_m`: 제한 적용 후 중심 조향각과 후륜축 중심 기준 회전반경
- `front_deg_l/r`: Ackermann 식으로 계산한 물리 좌·우 전륜 조향각
- `target_rpm_l/r`, `rpm_l/r`: 좌우 목표 및 측정 모터 RPM
- `enabled_l/r`: 논리적인 드라이버 활성 상태. 정지 시 둘 다 0이어야 한다.
- `servo_us_l/r`: 실제 생성되는 서보 펄스
- `enc_l/r`: 좌우 누적 quadrature 카운트

## 7. 최초 시험 순서

최초 시험은 반드시 **바퀴를 지면에서 띄우고** 진행한다.

1. 모터용 24 V 전원을 끈 상태에서 Uno와 서보 전원만 켠다.
2. 서보가 중앙으로 이동하는지 확인한다. 설정된 중앙 보정값은 좌 1398 us, 우 1402 us이며 4 us 타이머 해상도에서의 실제 출력은 각각 1400 us, 1404 us이다.
3. 작은 각도부터 `@STEER 1`, `@STEER -1`, `@CENTER`를 순서대로 보내 양수에서 좌회전, 음수에서 우회전, 중앙 복귀가 맞는지 확인한다. 방향과 기구 간섭을 확인하기 전에는 한계각을 명령하지 않는다.
4. `@STATUS`에서 `enabled_l=0 enabled_r=0`인지 확인한다.
5. 좌우 바퀴를 손으로 돌려 `enc_l`, `enc_r`이 각각 변하는지 확인한다.
6. 모터 전원을 켜고 `@MOTOR 10 0` 후 즉시 `@MOTOR 0 0`으로 좌측만 시험한다.
7. `@MOTOR 0 10` 후 즉시 `@MOTOR 0 0`으로 우측만 시험한다.
8. 양수 명령에서 바퀴가 차량 전진 방향과 반대로 돌면 해당 `POWERON_*_DIR_FORWARD_IN1_HIGH` 값만 반전한다.
9. 모터 라벨의 실제 `1/xx` 감속비와 알려진 회전수당 실제 카운트를 설정한다.
10. 양쪽 A/B 부호와 출력 전압을 확인하고 PID를 바퀴를 띄운 상태에서 조정한 뒤 `POWERON_CLOSED_LOOP_READY` 조건을 충족시킨다.
11. 새로 빌드한 뒤 `@DRIVE 0.05 0`부터 폐루프 제어를 시험한다.

엔코더가 움직이지 않는데 폐루프 주행 명령을 내리면 PID가 높은 출력으로 올라갈 수 있다. 두 엔코더가 모두 정상적으로 측정되기 전에는 `@DRIVE`를 사용하지 않는다.

## 8. 구현된 안전 조치

- 부팅 전에 Low-active ENABLE 출력 래치를 HIGH로 선설정
- 정지 시 ENABLE 비활성, PWM LOW, IN1/IN2 LOW
- 방향 변경 시 출력 차단 및 50 ms 정지 구간
- 1.5초 명령 watchdog
- 시리얼 입력 처리량 제한으로 제어 루프 기아 방지
- 너무 긴 라인은 줄 끝까지 모두 폐기하여 남은 문자가 주행 키로 실행되는 현상 방지
- 조향 시 좌우 속도 비율은 유지하면서 어느 바퀴도 0.60 m/s를 넘지 않도록 제한
- 서보별 실측 안전 펄스 범위 적용
