# 라이다 벽 추종 자율주행

현재 차량의 두 후륜은 각각 모터와 엔코더를 갖습니다. 기본 듀얼 후륜 펌웨어는 Pi에서 보내는 `LIDAR START`·`LIDAR DRIVE`를 거절합니다. 이 구성에서 사용할 수 있는 기능은 USB·SSH 스캔 기록, 경로 계획 미리보기와 오프라인 재생입니다. 아래 실주행 예시는 기존 단일 후륜 펌웨어용입니다. 두 후륜 차량의 라이다 자율주행은 실물 검증 전입니다. [듀얼 후륜 제어](../../vehicle/firmware/dual-rear.ko.md)

RPLIDAR A1을 차량 중앙에 고정합니다. 라이다 USB를 Raspberry Pi에 연결합니다. Pi는 한 바퀴의 거리·각도 데이터로 조향각과 전진 출력을 계산합니다. 주행 모드에서는 Pi가 Nano 33 IoT에 TCP 명령을 전송합니다.

[가상 트랙 사용법](../../simulation/track/guide.ko.md) · [반복 스트레스 시험](../../simulation/benchmark/guide.ko.md)

## 1. Windows에서 명령 미리보기

라이다 시각화 창에서 **정지**를 눌러 Pi의 USB 포트를 해제합니다. [라이다 연결 매뉴얼](../acquisition/setup.md)

Windows PowerShell에서 아래 명령을 실행합니다. Pi 계정 비밀번호를 입력합니다. 이 모드에서는 Nano에 접속하지 않습니다.

```powershell
cd C:\Users\user\Arduino\Nano_33_IoT
python -m lidar.autopilot --ssh user@andrea.local --seconds 10 --scan-timing
```

기록 파일로도 같은 계산을 실행할 수 있습니다.

```powershell
python -m lidar.autopilot --csv build/lidar_captures/20261111_154213/scan.csv --scan-timing
python -m lidar.autopilot --session "주행 데이터/회차폴더" --scan-timing
```

세션 재생은 저장된 회전·표본 시각과, 수집한 경우 당시의 뒷차축 자세를 다시 사용합니다. 피드백이 없는 회차는 이동 범위 추정으로 계산합니다. 재생에는 Nano 연결이 필요하지 않습니다. 라이다를 한 곳에 고정한 미리보기에는 `--stationary-preview`를 추가합니다. 차량을 손으로 밀거나 굴리는 미리보기에는 이 옵션을 생략합니다. [회차별 파일·버전 비교](../../vehicle/drive_data/guide.ko.md)

시간 진단은 `rx_rotation`(회전 시작 표식의 수신 간격), `points`(점 수), `rx_rate`(초당 수신점), `estimated_ray_span`(각도에서 추정한 첫 점과 마지막 점의 시간 차이)을 표시합니다. RPLIDAR A1에서 사용하는 표준 패킷은 회전 시작 표식, 각도, 거리, 품질을 전송합니다. 개별 광선 시각은 각도 진행률과 호스트 수신 시각으로 근사하며 USB에서 여러 패킷을 한 번에 수신하면 오차가 생길 수 있습니다. [SLAMTEC RPLIDAR 통신 프로토콜](https://bucket.download.slamtec.com/f010c72be308cdc618e91746d643278185ed02b2/LR001_SLAMTEC_rplidar_protocol_v2.2_en.pdf)

| 출력 | 의미 |
| --- | --- |
| `follow walls` | 양쪽 벽이 보이고 차량이 지나갈 수 있는 경로를 찾았습니다. |
| `steer` | Nano 중심 조향 목표입니다. 양수는 왼쪽, 음수는 오른쪽입니다. |
| `PWM` | 전진 모터 출력 비율입니다. 실제 속도는 차량에서 측정합니다. |
| `clear` | 차량의 예상 경로에서 확인한 전진 가능 길이입니다. |
| `motion=deskew` | 시간에 맞춘 자세로 광선의 시작점과 반사점을 모두 보정했습니다. |
| `motion=bounded` | 자세 입력이 없습니다. 스캔 시간과 설정한 최대 속도·최소 회전반경으로 가능한 이동 범위를 계산했습니다. `origin_bound`와 `yaw_bound`는 이 조건에서 계산한 여유입니다. |
| `motion=stationary` | 고정 미리보기 또는 차량이 정지해 있어야 하는 출발 전 초기 확인입니다. |
| `insufficient clear distance` | 장애물, 가까운 벽, 또는 관측 범위 부족으로 정지거리를 확보할 수 없습니다. |
| `insufficient wall support` / `incomplete scan` | 벽 추정 또는 스캔의 완전성이 부족합니다. 출력은 0%입니다. |

## 2. 조향을 계산하는 방법

코너, 벽 단절, 폭 변화와 다양한 센서·차량 조건의 처리 범위는 [주행 원리와 상황별 설계](planning/track-planning.ko.md)를 확인합니다.

1. 한 바퀴 스캔을 차량 기준 좌표로 변환합니다. 차량 정면과 라이다의 0° 차이를 `--forward-angle`로 보정합니다. 평평한 벽을 정면에 놓고 여러 거리에서 실측과 스캔의 차이를 확인합니다. 차이가 거리에 따라 거의 일정하면 측정값에서 실측값을 뺀 값을 `--range-offset-mm`에 입력합니다.
2. 현재 자세에서 좌우 조향 후보의 이동 경로를 계산합니다. 계산에는 Nano 펌웨어와 같은 133.24 mm 축간거리를 사용합니다.
3. 각 경로를 따라 차량 폭과 앞뒤 길이를 적용합니다. 벽이나 장애물에 닿을 경로와 전방 관측이 부족한 경로를 제외합니다.
   - 전방 벽 때문에 좌우 회전이 둘 다 가능해 보이면 각 방향의 경로를 더 멀리 확인합니다. 양쪽 모두 가능하거나 어느 쪽도 충분히 보이지 않으면 정지합니다. 한쪽만 이어지면 그 방향을 제한 속도로 평가합니다.
4. 남은 경로의 여러 단면에서 왼쪽과 오른쪽 벽까지의 거리를 추정합니다. 양쪽 거리가 비슷하고 더 멀리 확인된 경로를 우선합니다.
   - 코너 너머가 가려져도 차 가까이의 연속된 네 단면에서 양쪽 벽이 측정되면 폭을 갱신할 수 있습니다. 한쪽만 측정됐을 때는 기존 폭의 유효 시간을 연장하지 않습니다.
5. 선택한 경로의 곡률에서 허용 속도를 구합니다. 같은 반경에서 속도가 2배가 되면 필요한 횡가속도는 4배가 됩니다. 실제 최소 회전반경을 벗어나는 조향 후보는 제외합니다. [차량 운동학 모델](https://escholarship.org/content/qt6b7015sp/qt6b7015sp.pdf)
6. 현재 방향의 직선 경로가 먼저 막히면 코너까지 남은 거리를 추정합니다. 지연 중 이동 거리와 실측 감속도를 반영해 코너 진입 전 목표 속도를 낮춥니다. 목표 속도와 정지거리가 늘면 경로를 더 멀리 확인합니다. 급한 코너에는 보정한 최소 회전반경도 적용합니다.
7. 코너에서 설정된 속도 상한을 유지합니다. 직선에 가까운 경로와 전진 여유를 두 스캔 연속 확인하면 코너 속도 상한을 해제합니다. 목표 속도를 단계적으로 높입니다. 정지거리와 벽 인식 기준을 만족하는 경로가 없으면 0%를 출력합니다.

계획기가 표시하는 목표 속도는 PWM 보정값을 기반으로 합니다. 동기화된 자세나 두 엔코더 카운트를 입력한 경우 `measured`에 추정한 차체 속도가 함께 표시됩니다. 바퀴가 헛돌면 엔코더와 지면 이동 속도에 차이가 생깁니다. Nano에서 PWM을 끈 뒤에도 관성으로 이동할 수 있습니다.

### 움직이면서 측정한 스캔

Pi USB 직결에서는 계획 계산과 별도로 회전 데이터를 계속 읽습니다. 계산기가 늦어지면 완성된 회전 중 가장 최근 것을 가져옵니다. 표준 스캔의 회전 표시 위치를 USB 수신 시각과 뒤따른 직렬 바이트 수로 추정하고, 표시 사이에서 수신한 표본 순서로 광선 시각을 배정합니다. 라이다의 순간 각속도가 변해도 각도에 비례해 시간을 배정하지 않습니다. 이 시각은 추정값이며 USB 지연과 장치 내부 지연은 포함할 수 있습니다. [SLAMTEC 표준 스캔 프로토콜](https://bucket.download.slamtec.com/63ac3f0d8c859d3a10e51c6b3285fcce25a47357/LR001_SLAMTEC_rplidar_protocol_v1.0_en.pdf)

자세 입력이 있으면 각 광선의 시각에 맞춰 뒷차축 위치와 차체 방향을 보간합니다. 라이다 장착 위치를 적용하고 광선의 시작점과 반사점을 회전 종료 시점의 차량 좌표로 옮깁니다. 정면 관측 범위도 이 좌표에서 다시 계산합니다. 자세 간격이 60 ms를 넘거나 스캔 양끝을 포함하지 않으면 미리보기 PWM은 0으로 표시합니다. 주행 중 자세 입력의 일시적 누락은 확인 경로 유지와 복구 절차를 적용합니다.

주변 여러 반사점이 같은 벽을 지지할 때, 벽보다 홀로 멀리 찍힌 광선은 그 뒤를 빈 공간으로 표시하는 데 사용하지 않습니다. 홀로 가까이 찍힌 점은 장애물 검사에 남기고, 자세로 보정한 스캔에서는 벽 추정에서만 제외합니다. 그 점만 경로를 막으면 모터 출력을 0으로 낮추고 같은 경로로 전진하는 대신 유효한 새 스캔 두 번을 확인합니다. 여러 점이 막고 있거나 재확인 시간이 초과되면 정지합니다.

자세 입력이 없으면 출발 후의 스캔 시간과 처리 지연 동안 차가 어디까지 움직이고 돌아갔을 수 있는지 계산합니다. 충돌을 판단할 차체 범위를 키우고, 범퍼 방향의 관측 범위가 부족하면 전진 여유를 줄입니다. 이 경우 주행 목표 속도에는 0.20 m/s 상한을 적용합니다. 실제 이동 범위 계산에는 `--max-speed`에 입력한 최대 실측 속도를 사용하므로, 좁은 트랙이나 느린 스캔에서는 목표 속도가 낮아도 정지할 수 있습니다.

#### 자세 데이터 연결

동일 시각의 좌우 후륜 원시 카운트가 있으면 `--encoder-csv 엔코더.csv`를 쓸 수 있습니다. 헤더는 `timestamp_s,left_count,right_count`이고 타임스탬프는 로컬 라이다와 같은 단조 시각(초)입니다. 공용 `dual_rear`에 실측 후륜 간격, 양쪽 타이어 둘레·카운트·부호와 바퀴 속도 상한을 채워야 합니다. 전진·선회의 추정 자세를 스캔과 맞추며, 샘플 간격이 60 ms를 넘는 스캔은 자세 보정에 사용할 수 없습니다. 카운터 재시작·불연속 구간은 회차를 나눕니다. 옵션을 생략하면 기존 자세 CSV 또는 미계측 경로를 사용합니다.

1. 뒷차축 중앙의 위치와 차량 방향을 계산하는 프로그램이 정규 CSV 파일에 자세를 추가하게 설정합니다. 첫 줄은 `timestamp_s,x_m,y_m,yaw_deg`입니다. 행마다 줄바꿈을 쓰고 데이터를 즉시 플러시합니다. 표본 간 간격이 60 ms 이하가 되도록 25~50 Hz로 기록합니다.
2. 실시간 USB에서는 `timestamp_s`에 라이다를 읽는 Pi와 같은 `time.monotonic()` 시각을 초 단위로 기록합니다. 재생은 스캔 CSV에 `sample_timestamp_s` 열이 있으면 그 시각을 직접 사용합니다. 기존 CSV는 `host_receive_elapsed_s`의 회전 표시와 표본 순서로 시각을 추정합니다. 자세 파일에는 해당 스캔 파일과 같은 시간 기준을 사용합니다. `x_m`, `y_m`는 미터 단위입니다. x축 정방향이 0°이며, y축 정방향 쪽으로 시계 방향 회전하면 `yaw_deg`가 증가합니다.
3. Pi USB 미리보기 명령이나 실차 주행 명령에 `--pose-csv /경로/poses.csv`를 추가합니다. 기록을 재생하려면 `python -m lidar.autopilot --csv scan.csv --pose-csv poses.csv --scan-timing`을 실행합니다. 로그의 `motion=deskew`는 자세 보정, `ray_clock`은 표본 시각의 출처, `far_rejected`와 `near_suspect`는 고립 반사점 검사 결과입니다. 현재 차량 구성에는 동기화된 자세 파일을 자동으로 만드는 센서 경로가 연결되어 있지 않습니다.

앞바퀴 각도를 직접 측정할 수 있으면 CSV의 마지막 열에 `steer_deg`를 추가합니다. `steer_deg`는 실제 바퀴 각도를 도로 기록합니다. 직진은 0°이고 왼쪽이 양수입니다. `yaw_deg`는 차량 방향이며 시계 방향이 양수입니다. 자세로부터 속도와 회전율을 구하므로 기존 네 열 CSV도 읽습니다. 이때 속도가 충분하면 회전율과 속도로 차량이 실제로 그린 곡률을 추정합니다. 서보 명령 각도는 `steer_deg`의 입력으로 사용할 수 없습니다.

피드백을 사용하는 경우 `--steering-delay-ms`에 느린 조향 지연, `--steering-rate-deg-s`에 부하가 걸렸을 때의 낮은 조향 변화율, `--propulsion-delay-ms`에 구동 응답 지연을 입력합니다. 현재 예시 기본값은 각각 80 ms, 75°/s, 85 ms입니다. 로그의 `target`, `measured`, `steer`, `actual_steer`와 `response`를 비교합니다. `coast`는 모터 출력을 끄고 관성으로 감속하는 명령입니다. [시뮬레이션과 실차 사이의 차이](planning/track-planning.ko.md#시뮬레이션과-실차-사이의-차이)

## 3. 차량 장착 상태 확인

[부품별 장착 상태](../../hardware/README.md)와 [차체·조향 측정 기준](../../hardware/control-parameters.ko.md)을 함께 확인합니다.

1. 차를 트랙 직선의 중앙에 놓습니다. 라이다의 측정면이 벽과 만나도록 높이를 맞춥니다.
2. 레이더에서 차량 정면에 놓은 상자의 각도를 확인합니다. 이 각도가 `--forward-angle`입니다.
3. 바퀴를 포함한 최대 차폭을 미터로 잽니다. 이 값이 `--width`입니다.
4. 라이다 중심에서 차 앞끝과 뒤끝까지의 거리를 각각 잽니다. 이 값이 `--front`, `--rear`입니다.
5. 뒷차축에서 라이다 중심까지의 전후 거리를 잽니다. 이 값이 `--sensor-ahead`입니다.
6. 실제 쓰려는 최대 PWM에서 정지 여유를 확인합니다. 센서 갱신과 명령 만료까지 이동하는 거리, 관성으로 더 이동하는 거리, 여유분을 합쳐 `--stop-distance`를 정합니다. 펌웨어의 명령 만료 시간은 500 ms입니다.
7. 미리보기 명령에 측정값을 입력합니다. 중앙에서 조향이 0°에 가까운지 확인합니다. 차를 한쪽 벽에 가깝게 옮겨 반대쪽으로 조향하는지 확인합니다.
8. 저속으로 일정하게 원을 그릴 때 뒷차축 중앙의 궤적 반지름을 잽니다. 조향이 가장 많이 들어간 좌우 회전 중 큰 반지름을 `--min-turn-radius`에 사용합니다.
9. 직선에서 기동 PWM과 의도한 상한 PWM의 정상 속도를 확인합니다. 거리 눈금을 두고 영상을 찍으면 프레임과 이동 거리로 속도를 구할 수 있습니다.
10. 기동 후 속도가 올라가는 구간과 PWM을 줄인 뒤 속도가 내려가는 구간의 속도 변화를 잽니다. 시간당 속도 변화로 가속·감속도를 구합니다. 감속도에는 반복 시험에서 느리게 멈춘 조건을 반영합니다.
11. 지연에는 스캔을 기다리는 시간, 계산 시간, 명령이 동작으로 나타날 때까지의 시간을 합합니다. 회전 시험은 실측 반경에서 확인한 낮은 속도를 기준으로 횡가속 한계를 보수적으로 정합니다.

## 4. Pi에서 주행 준비

Windows PowerShell에서 프로젝트 루트로 이동한 뒤 파일을 복사합니다.

```powershell
ssh user@andrea.local "mkdir -p ~/poweron-lidar/vehicle ~/poweron-lidar/hardware"
scp -r lidar user@andrea.local:poweron-lidar/
scp vehicle/__init__.py user@andrea.local:poweron-lidar/vehicle/
scp -r vehicle/wifi vehicle/manual_control user@andrea.local:poweron-lidar/vehicle/
scp -r vehicle/drive_data user@andrea.local:poweron-lidar/vehicle/
scp hardware/__init__.py hardware/control_profile.json user@andrea.local:poweron-lidar/hardware/
```

Pi 터미널에서 USB 직결 미리보기를 실행합니다.

```bash
cd ~/poweron-lidar
python3 -m lidar.autopilot --port /dev/ttyUSB0 --seconds 10
```

실제 명령을 보내려면 Nano에 명령별 유효시간을 지원하는 [펌웨어](../../vehicle/firmware/PowerOnNano/PowerOnNano.ino)가 필요합니다. Pi에는 앞 절의 파일을 복사합니다. 처음에는 모터 전원을 분리한 상태로 Nano 응답, 실제 조향 방향, 라이다를 끊고 연결했을 때의 출력을 확인합니다. Nano는 제어 연결을 하나만 받으므로 아래 콘솔을 사용할 때는 별도의 조종기와 센서 모니터를 종료합니다.

**아래 대문자 항목을 측정값으로 바꾼 뒤** Pi 터미널에서 실행합니다. Windows 키보드로 조종하려면 PowerShell에서 `ssh -t user@andrea.local`로 접속한 뒤 Pi 터미널에서 같은 명령을 실행합니다.

```bash
python3 -m lidar.autopilot --port /dev/ttyUSB0 --drive --interactive --host NANO_IP \
  --forward-angle FORWARD_DEG --sensor-ahead REAR_AXLE_TO_LIDAR_M \
  --width WIDTH_M --front FRONT_M --rear REAR_M --stop-distance STOP_M \
  --pwm MAX_PWM --min-turn-radius TURN_RADIUS_M --max-speed SPEED_MPS \
  --acceleration ACCEL_MPS2 --deceleration DECEL_MPS2 --lateral-accel LATERAL_MPS2 \
  --delay-ms DELAY_MS --deadband-pwm MIN_PWM --seconds 30
```

### 자율주행과 수동조종 전환

차량을 정지시킨 상태에서 콘솔을 실행하면 수동조종 모드로 시작합니다. 두 모드가 Pi의 같은 Nano 연결을 사용합니다.

| 키 | 동작 |
| --- | --- |
| `1` / `G` | 자율주행 요청. 정지 대기 후 유효한 스캔 3개를 연속 확인하면 출발합니다. |
| `0` / `-` / `I` | 정지·조향 중앙, 수동조종으로 고정. 자동 복귀를 취소합니다. |
| `W` / `S` / `A` / `D` / `C` | 수동으로 제어권을 가져옵니다. 통신 복구나 관성 정지 대기 중 입력은 버리므로 준비되면 다시 누릅니다. |
| `X` / `Space` | 모터를 정지하고 자동 복귀를 취소합니다. |
| `B` | 현재 모드와 자동 복귀 대기 여부를 표시합니다. |
| `Q` / `Esc` | 정지하고 종료합니다. |

자율주행이 복구 가능한 동안에는 자율 모드를 유지합니다. 정지해야 하면 `IDLE`을 보내고 수동 대기로 전환합니다. Nano 응답이 끊겨 정지를 확인할 수 없으면 명령 유효시간과 관성 정지 시간을 기다립니다. 수동 키로 제어권을 가져가기 전에는 센서와 Nano 연결을 계속 확인하며, 새 스캔 3개와 정지 여유가 확인되면 자율주행으로 복귀합니다. 수동으로 고정한 뒤에는 `1`을 다시 누릅니다.

Pi는 매 자율주행 명령에 Nano가 적용할 유효시간을 붙입니다. 유효시간은 **최대 500 ms**입니다. 스캔 기준 시각 이후 이동한 거리, 동작 지연, 관성 이동 거리와 여유를 확인된 경로에서 뺍니다. 점별 자세 보정한 스캔의 좌표 기준은 회전 종료 시각입니다. 회전할 때는 같은 조향으로 확인한 경로 구간만 사용합니다. 정지 여유가 충분해야 다음 회전까지 유효한 명령을 보냅니다.

실차에서는 기본적으로 명령이 지속되는 동안 `--max-speed`까지 움직일 수 있다고 계산합니다. 속도 오차를 계측한 경우에만 `--speed-error-mps E`로 더 정밀하게 계산할 수 있습니다. `E`는 스캔 종료 시각의 **실제 차체 전진 속도가 계측 속도보다 클 수 있는 최대 차이(m/s)**입니다. 엔코더 분해능, 속도를 평균한 시간 동안의 가속, 시계 오차와 바퀴 미끄럼을 포함합니다. 같은 시각의 영상 또는 외부 위치 측정을 기준으로 노면·하중·배터리별 상한을 얻습니다. 이 옵션을 쓰면 계측 속도에 `E`를 더한 뒤 `--acceleration`까지 가속할 수 있는 거리, 지연과 `--deceleration` 기준의 정지 여유를 함께 계산합니다. 가속 입력에는 해당 조건에서 가능한 가속도의 상한을 씁니다. 가상 시험의 기본 속도 오차 0.02 m/s는 시뮬레이션 설정입니다.

동기화된 속도와 오차 상한을 제공한 경우 `--stop-distance`에는 실제 정지 판단부터 통신·구동 응답과 관성 이동을 거쳐 완전히 멈출 때까지의 거리를 넣습니다. 계획기는 명령 유효시간까지 진행한 뒤 이 실측 정지 거리를 확보합니다. 별도로 명령 지연 내내 가속한 뒤 설정된 감속도로 정지하는 거리도 계산하고 둘 중 긴 쪽을 사용합니다.

양쪽 벽과 앞쪽 경로를 연속 확인하고 곡률·정지거리 조건을 만족하면 `--max-speed`까지 가속합니다. `--pwm`은 그 실측 최고속도에 대응하는 출력 상한입니다. 경로가 다시 확인된 순간 차가 굴러가고 있으면 관측 속도와 새 경로의 속도 한도에서 추종을 재개합니다. 관측 여유가 충분한 완만한 감속에서는 PWM을 낮추고, 낮춘 PWM으로 실제 속도가 떨어지지 않거나 현재 속도에 필요한 공간이 부족하면 출력을 끕니다. 한계 부근의 엔코더 과속 추정은 첫 프레임에서 출력을 끄고 재확인합니다. 과속이 크거나 새 계측 프레임에도 지속되면 주행 세션을 정지합니다.

자세 계측 없이 출발할 때는 실제로 정지해 있어야 합니다. Pi는 새 스캔이 들어오는 동안 확인된 모터 출력 이력과 가속·감속 한계로 스캔 한 바퀴의 가능한 이동 범위를 계산합니다. 미계측 주행의 목표 속도 상한은 0.20 m/s입니다. 움직일 수 있는 공간과 명령 유효시간은 계속 실측 최고속도 기준으로 확인합니다.

### 주행 중 스캔이 불완전할 때

- **짧은 누락**은 직전 명령의 조향과 이미 확인한 통로를 사용합니다. 최근 스캔 종료 후 최대 500 ms를 한도로 하고, 그동안 이동했을 거리와 정지 여유를 매번 차감합니다. 목표 속도는 최대 0.15 m/s입니다. 불완전한 스캔으로 기존 통로의 거리나 시각을 갱신하지 않습니다.
- **남은 여유가 부족하거나 분기 방향이 불확실하면** 같은 세션에서 구동 출력을 끄고 최대 2초 동안 기다립니다. 주행 가능한 새 스캔 두 개를 연속으로 받고 다음 스캔까지 정지 여유를 유지할 수 있으면 다시 출력합니다. 시간이 지나도 통로가 확인되지 않거나 가까운 장애물이 확인되면 세션을 종료합니다.
- **USB나 Nano 연결이 끊기면** 통신이 남아 있는 경우 Pi가 정지 명령을 보냅니다. Nano에 도달할 수 없는 경우에는 마지막 명령의 유효시간이 끝나면 Nano가 출력을 끕니다. 정지 대기 후 새 스캔 3개로 통로를 다시 확인합니다.
- **예상한 다음 회전이 40 ms 여유 안에 도착하지 않거나 동기 자세가 중단되면** PWM을 0으로 내립니다. 같은 연결에서 정상 데이터가 돌아오면 새 계획 두 개의 여유를 확인합니다.

`--seconds`를 지정하면 수동조종·자율주행과 재연결을 그 시간까지 실행합니다. `Ctrl+C`로도 종료할 수 있습니다. 키 입력이 필요 없는 기존 단독 자율 실행은 `--drive`만 사용합니다.

`--max-speed`에는 해당 PWM에서 예상되는 높은 쪽 실측 속도를 입력합니다. `--deceleration`에는 해당 노면에서 느리게 멈춘 경우의 감속도를 입력합니다. L298N은 출력을 차단한 뒤에도 관성으로 이동하므로, 이 수치로 정지 여유와 재출발 대기 시간을 계산합니다. [L298 데이터시트](https://www.st.com/resource/en/datasheet/l298.pdf)

계산 전용 모드에서 USB나 SSH가 끊기면 자동으로 재연결합니다. Pi에 여러 USB 어댑터가 있다면 `--port /dev/serial/by-id/장치이름`처럼 전체 경로를 지정합니다. SSH 미리보기에서도 `--port`는 Pi에 있는 장치 경로를 가리킵니다.

## 검증 범위

Pi에서 실제 스캔 30회를 받아 계산 전용 모드를 확인했습니다. 당시 배치에서는 전진 여유가 부족해 출력이 0%였습니다. Nano 펌웨어 컴파일, 모의 직선·좌우 90° 코너·막힌 길, 지연 스캔에서의 명령 차단도 확인했습니다. 실제 차량의 조향 방향과 제동거리 확인 및 트랙 주행 시험이 남아 있습니다. [개발 기록](../../docs/development-log.ko.md#2026-11-19-pi-라이다-벽-추종-계산-확인)
