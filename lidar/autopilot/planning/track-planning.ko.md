# 라이다 트랙 주행 원리와 상황별 설계

## 현재 구현

Pi는 라이다 한 바퀴를 차량 기준 좌표로 변환합니다. 센서 정면 보정, 뒷차축 기준 센서 위치, 축간거리와 최소회전반경을 사용합니다. 전후좌우 거리 몇 개만 비교하는 방식보다 넓은 영역을 쓸 수 있습니다.

1. 조향각 29개에 대해 차량이 지나갈 경로를 계산합니다. 회전 경로는 뒷차축을 기준으로 계산합니다.
2. 각 경로에서 약 4.5 cm 간격으로 차량의 폭과 앞뒤 길이를 검사합니다. 안전 여유를 더한 차체 안에 실제 라이다 점이 들어오면 해당 구간에서 경로를 자릅니다. 앞범퍼 중앙과 양 끝이 관측된 영역 안에 있는지도 검사합니다.
3. 차체 경로에 수직인 여러 단면에서 좌우 벽을 찾습니다. 통과가 확인된 길이, 좌우 간격의 균형, 벽 확인 비율, 이전 조향과의 차이로 조향 경로를 고릅니다.
4. 선택 경로의 곡률과 앞쪽에서 확인한 거리로 속도를 제한합니다. 코너 진입까지의 거리에 먼저 감속할 수 있어야 합니다. 코너에서 감속한 경우 직선에 가까운 경로를 두 스캔 연속 확인하고 다시 가속합니다.
5. 일시적인 관측 누락에는 직전 경로의 거리와 시간 여유 안에서 감속합니다. 그 여유가 줄면 구동 출력을 끄고 새 관측을 기다립니다. 같은 세션의 관측 복구에는 새 스캔 2개가 필요합니다. 연결이 끊겨 다시 연결한 경우에는 새 스캔 3개가 필요합니다. 주행 명령은 관성 이동 거리를 남긴 범위에서 최대 500 ms까지 유효합니다. [복구 절차](../guide.ko.md#주행-중-스캔이-불완전할-때)

## 벽이 끊기거나 갑자기 벌어질 때

| 관측 | 현재 동작 |
| --- | --- |
| 양쪽 벽이 연속적으로 보임 | 실제로 측정한 쌍으로 중앙 경로를 고릅니다. 차 가까이에서 일관된 폭을 새 스캔 3개에서 확인하면 폭 기준을 갱신합니다. |
| 한쪽 벽이 잠깐 끊기거나 멀어짐 | 차 가까이부터 연속적으로 보이는 한쪽 벽과 최근 폭을 사용합니다. 같은 쪽 벽이 여러 단면에서 이어져야 합니다. 추정한 폭은 새 기준값으로 기록하지 않습니다. |
| 옆이 갑자기 벌어짐 | 최근 폭보다 큰 단면을 정상적인 좌우 쌍에서 제외합니다. 믿을 수 있는 벽을 따라가되 목표 속도를 설정한 상한의 40%와 0.20 m/s 중 낮은 값으로 제한합니다. 양쪽 벽 관측이 회복된 뒤 새 스캔 2개를 확인하고 제한을 해제합니다. |
| 한쪽 벽만 오래 보이거나 양쪽이 동시에 멀어짐 | 직전 폭으로 벽을 추정할 수 있는 시간은 마지막으로 확인한 폭에서 1.2초입니다. 근거가 부족하면 정지합니다. 큰 폭 변화가 실제 정규 트랙인지 판단하려면 경로 정보가 필요합니다. |
| 진행 방향 앞범퍼 한쪽이 가려짐 | 중앙 광선의 거리가 길어도 양 끝까지 확인할 수 있는 범위까지만 경로를 인정합니다. 정지 여유가 부족하면 정지합니다. |

이 방식은 부분적으로 보이는 경계에서 폭을 이용해 중앙선을 확장하는 F1TENTH 지역 지도 연구를 참고했습니다. 현재 구현에서는 추정 경계를 조향 평가에만 사용합니다. 통과 여유는 실제 스캔으로 확인합니다. [F1TENTH 벤치마크 구현](https://github.com/hawaii-nc/f1tenth_benchmarks) · [지역 지도 추출 알고리즘 논문](https://f1tenth.github.io/publications/Local_Maps.pdf)

장애물 가장자리에서 차량 폭을 고려하는 F1TENTH Disparity Extender와 Follow the Gap도 참고했습니다. 현재 경로 선택은 장애물 옆의 가장 넓은 열린 공간에 바로 조향하는 대신, 차체를 포함한 경로와 최근 통로의 연속성을 검사합니다. [F1TENTH Follow the Gap 실습](https://github.com/f1tenth/f1tenth_lab4_template) · [Disparity Extender 연구팀 저장소](https://github.com/karpenet/Reactive-Methods-for-Autonomous-Racing)

## 다른 차량이 없는 폐회로 주행

- 코너 바로 앞이나 가려진 코너 너머에서 최근 통로 폭과 맞는 양쪽 벽이 연속해서 측정되면 해당 방향으로 제한 속도로 진행합니다. 앞범퍼와 차체 여유는 기존 충돌 검사로 확인합니다. 좌우 탈출 경로가 모두 그럴듯한 분기, 관측 부족, 정지 여유 부족에서는 정지합니다.
- 차가 벽을 비스듬히 볼 때 두 벽의 기울기가 일치하는 구간에서는 통로 폭의 투영을 보정합니다. 양쪽 벽을 실제로 연속 측정한 구간에만 적용하며 이때도 제한 속도를 사용합니다.
- 현재 바퀴 각도에서 새 조향이 적용될 때까지의 궤적을 따라 곡률과 구간별 속도 한계를 계산합니다. 앞쪽의 각 곡률 한계까지 반응 지연과 감속을 고려해 현재 가능한 속도를 구합니다. 계측된 조향에서 궤적을 예측할 때는 설정한 횡가속도의 85%를 속도 계산에 사용합니다. [TUM 궤적 속도 계획](https://github.com/TUMFTM/trajectory_planning_helpers)
- 실제 앞바퀴 각도 센서가 연결되면 조향이 안정된 표본으로 중립 편차와 좌우 배율을 제한된 범위에서 갱신합니다. 회전 반응 이상, 큰 조향 오차, 정해진 배율 범위를 벗어난 표본은 제외합니다.
- 벽 확인 부족이나 구동 이상으로 생긴 임시 속도 제한은 코너 속도 한계와 독립적으로 적용합니다. 센서 신뢰도가 회복되면 곡률과 정지거리 조건 안에서 다시 가속합니다.

## 상황별 설계와 검증 범위

| 상황 | 필요한 판단과 동작 | 현재 범위 |
| --- | --- | --- |
| 평행 직선, 시작할 때 한쪽으로 치우침, 차량 각도 틀어짐 | 여러 단면 중앙으로 조향합니다. 벽 가까이 시작하면 실제 차폭과 앞뒤 돌출부가 처음부터 들어가는지 검사합니다. | 모의 확인 |
| 완만한 좌·우 곡선, 연속 코너, S자 | 열린 공간의 중심이 움직여도 지난 경로와 연속되는 조향을 선택합니다. 다음 코너의 감속 여유를 유지합니다. | 좌우 직각과 사각 순환 모의 확인. S자와 고속 연속 곡선 별도 확인 |
| 직각 코너, 바깥쪽 벽은 보이지만 안쪽이 가려짐 | 직선 경로가 먼저 끝나면 감속합니다. 안쪽 앞바퀴와 바깥쪽으로 회전하는 차체 뒤쪽도 충돌 검사에 포함합니다. | 모의 확인 |
| 헤어핀, 최소회전반경보다 좁은 코너 | 적용 가능한 조향각에서 실제 차체가 지나갈 수 있는 후보가 없으면 정지합니다. 차량을 제자리에서 돌리거나 확인 없이 후진하지 않습니다. | 실제 헤어핀 별도 확인 |
| 천천히 좁아지거나 넓어지는 통로 | 여러 단면에서 양쪽 폭이 일관되면 기준을 천천히 갱신합니다. 차폭과 안전 여유를 확보할 수 없으면 정지합니다. | 폭 갱신 구현. 다양한 각도와 재질에서 실측 필요 |
| 한쪽 벽 틈, 기둥 사이, 옆방, 피트 입구 | 최근 폭과 이어지는 벽으로 제한적으로 진행합니다. 실제 관측으로 전진 가능 범위를 확인합니다. | 짧은 단절과 깊어진 옆 공간을 단위 시험. 시야가 부족한 가상 틈과 큰 옆방에서는 감속 후 정지 |
| 양쪽 벽이 장시간 끊김, 넓은 광장, 양쪽이 급격히 넓어짐 | 위치나 경로 단서가 없으면 주행 경로 확정을 보류합니다. 확인된 지도나 경로 마커가 있어야 목표 방향을 고를 수 있습니다. | 최근 폭과 일치하는 벽을 얻지 못하면 정지. 지도와 마커 연동은 설계 단계 |
| T자, Y자, 교차로, 추월 공간과 우회로 | 관측만으로 모두 갈 수 있는 길처럼 보일 수 있습니다. 정해진 주행 방향이나 경로 지도가 있어야 올바른 분기를 일관되게 선택합니다. | 직진보다 여유가 큰 좌우 후보가 비슷하면 정지합니다. 대칭 T자에서 확인했으며 일반 분기 분류는 설계 단계입니다. |
| 막다른 길, 막힌 코너, 역방향으로 놓인 차 | 정지거리를 넘길 만한 전진 후보가 없으면 정지합니다. 방향 전환과 후진은 별도 정책이 필요합니다. | 막다른 길 모의 확인. 후진 복구는 설계 단계 |
| 낮은 장애물, 높은 돌출부, 유리, 거울, 강한 햇빛, 반사율 낮은 재질 | 2D 라이다 높이에서 보이지 않거나 반사되어 거리값이 틀릴 수 있습니다. 트랙 재질을 바꾸거나 보조 센서와 물리 정지 수단을 검토합니다. | 유효값 부족 시 정지. 반사와 높이 문제 자동 식별은 설계 단계 |
| 움직이는 사람·차량, 갑자기 나타난 물체 | 최근 스캔을 자세에 맞춰 비교하고 상대속도와 충돌 예상 시간을 별도 계산합니다. 항상 관측 가능한 거리 안에서 멈출 수 있도록 속도를 제한합니다. | 현재 스캔의 장애물 위치를 평가. 속도 추정과 독립 충돌 감시기는 설계 단계 |
| 긴 직선 끝이 라이다 범위 밖, 이어지는 벽이 없거나 코너가 시야 밖 | 무응답은 관측되지 않은 영역으로 처리합니다. 멀리 보이는 광선 하나로 전진 속도를 높이지 않습니다. | 전방 반환과 범퍼 관측 검사 적용 |
| 스캔 일부 누락·USB·SSH 끊김·시간 지연 | 불완전하거나 오래된 스캔으로 출발하지 않습니다. 주행 중 USB가 끊기면 유효시간을 연장하지 않습니다. 재연결 후 신선한 통로가 확인되면 주행을 재개합니다. | 자동 재출발 모의 시험. 센서 수신은 별도 SSH 재연결 시험에서 확인 |
| 카펫·바닥 먼지·배터리 변화·타이어 슬립·경사 | 같은 PWM에서도 달라지는 실제 속도와 정지거리를 측정합니다. 엔코더와 IMU로 노면 변화와 조향 지연을 추정할 수 있습니다. | 자세 입력으로 속도와 회전율을 얻어 보정합니다. 노면별 제동거리 실측 필요 |
| 회전 스캔 중 차량 이동·방향 변화 | 광선마다 측정 시점의 자세로 시작점과 반사점을 변환합니다. 자세가 없을 때는 차체와 관측 범위에 이동·회전 여유를 두고 속도를 제한합니다. | 주행 코드와 CSV 재생의 `--pose-csv`에서 점별 보정 적용. 연결 장비의 동기화된 자세 데이터로 실차 검증 필요 |
| 경사로·진동·라이다 장착 틀어짐·부착물로 가림 | 장착 높이와 각도, 센서 0°, 차체 자체 반사를 확인합니다. 자세 변화가 크면 투영 오차가 커집니다. | 장착 각도 입력. IMU를 이용한 경사 보정은 설계 단계 |

## 시뮬레이션과 실차 사이의 차이

아래 목록은 현재 라이다·Pi·Nano 차량을 기준으로 합니다. 실제로 안전하게 사용할 수 있는 범위는 코스, 노면, 배터리와 장착 상태가 달라질 때 다시 확인합니다.

| 차이가 생기는 곳 | 확인할 원인 | 실제 주행에 생길 수 있는 문제 |
| --- | --- | --- |
| 조향 중심과 배율 | 서보 혼 정렬, 중립점, 조향 명령과 바퀴 각도 사이의 비선형 링크, 좌우 편차, 부호·단위 오류 | 직선에서 한쪽으로 밀립니다. 같은 각을 주어도 코너 반경이 달라집니다. 부호가 틀리면 벽 쪽으로 조향합니다. |
| 조향 가동 범위 | 최대 조향각, 좌우 최소 회전반경, 타이어와 차체 간섭, 서보 힘 부족 | 계획한 반경으로 돌지 못합니다. 안쪽 또는 바깥쪽 벽에 닿을 수 있습니다. |
| 조향 응답 | 명령 지연, 부하에 따른 서보 변화율, 기어 유격·백래시, 탄성, 방향 전환 때의 이력, 걸림 | 직선을 더 가다가 뒤늦게 꺾습니다. 연속 코너에서 이전 조향이 남아 중앙을 벗어납니다. 과보정으로 좌우 진동이 생깁니다. |
| 구동력과 가속 | PWM 데드밴드, 정지 마찰과 주행 마찰 차이, PWM·속도 비선형성, 모터와 드라이버 온도, 기어 손실 | 조금 올려도 출발하지 않거나 갑자기 튀어나갑니다. 일정 PWM에서도 실제 속도가 목표 위아래로 달라집니다. |
| 감속과 정지 | PWM 0에서의 관성 감속, 실제 브레이크 유무, 감속 응답 지연, 내리막, 고속에서의 감속 변화 | 감속을 시작해도 코너 진입 속도가 높습니다. 정지 판정 이후 예상보다 멀리 굴러갑니다. |
| 전원과 전기 | 배터리 충전량·전압 강하, L298N 전압 손실, 서보 유입 전류, 케이블 접촉, 과열·보호, 재부팅 | 가속이나 조향력이 변합니다. 명령을 받은 뒤 실제 동작이 늦어지거나 출력이 끊깁니다. |
| 질량과 형상 | 탑재 장비의 질량과 무게중심, 차체 길이·폭·축간거리, 라이다 위치, 바퀴 정렬·크기·압력 | 같은 조향에서도 코너 반경과 바깥쪽 차체 궤적이 달라집니다. 정지와 하중 이동이 예측과 다릅니다. |
| 타이어와 노면 | 마찰 변화, 타이어 온도·마모·미끄러짐, 먼지·물·이음매, 바퀴 뜸, 코너 중 동시 제동 | 바퀴는 꺾였어도 차체가 충분히 돌지 않거나 더 돌아갑니다. 급회전 중 제동에 쓸 수 있는 여유가 줄어듭니다. |
| 경사와 진동 | 오르막·내리막, 옆 경사, 요철, 차체 롤·피치와 센서 마운트 진동 | 속도가 과속이나 정체 쪽으로 변합니다. 라이다 측정면이 들리거나 내려가 벽과 바닥 반사가 섞입니다. |
| 라이다 광학 | 벽 재질·색, 검은 표면, 유리·거울, 강한 햇빛, 비스듬한 입사각, 거리·각도 해상도, 몸체에 의한 가림 | 벽이 끊겨 보이거나 존재하지 않는 먼 점이 생깁니다. 라이다 평면 위아래에 있는 물체는 빠질 수 있습니다. |
| 라이다 시간 | 회전률 변화, 한 바퀴를 읽는 동안의 주행과 회전, USB 버퍼·누락, 패킷 도착 시각과 측정 시각 차이 | 평평한 벽이 굽거나 코너가 기울어 보입니다. 오래된 자유 공간을 최신으로 오인할 수 있습니다. |
| 자세와 바퀴 측정 | IMU 드리프트, 엔코더 양자화·바퀴 헛돎, 좌표·시계 불일치, 센서 표본 누락, 얼어붙은 관측 | 실제 속도·회전율을 과소 또는 과대평가합니다. 잘못된 자세로 스캔을 보정하면 벽의 위치가 더 틀어집니다. |
| 처리와 통신 | Pi CPU 부하·스로틀링, 샘플 주기, USB·Wi-Fi 지터, 명령 재전송·누락, Nano 확인 응답과 실제 동작의 차이 | 예전 조향·PWM이 더 오래 유지됩니다. 센서가 정상이어도 계획이 늦어져 정지거리보다 가까워질 수 있습니다. |
| 코스와 장애물 | 실제 폭·곡률·벽 틈, 보이지 않는 다음 코너, 시야 가림, 움직이는 물체, 분기와 역방향 배치 | 가속할 구간을 잘못 고르거나 다른 통로로 빠질 수 있습니다. 사람이나 차량이 관측 뒤에 들어올 수 있습니다. |
| 운영과 고장 | 이전 세션 이동 잔류, 출발 위치·방향·속도, 바퀴 풀림, 연결 불량, 센서 또는 구동기 고장 | 정지 출발과 정상 구동 가정이 깨집니다. 같은 초기 명령에도 전혀 다른 경로로 움직일 수 있습니다. |
| 시뮬레이터와 설정 | 이상적인 지면·강체, 단순한 타이어, 제한된 난수와 시나리오, 충돌 검사 간격, 실제보다 좋은 센서 또는 잘못된 보정값 | 모의 완주를 그대로 재현하기 어렵습니다. 학습한 오차 보정값이 다른 환경에 맞지 않을 수 있습니다. |

예를 들어 0.42 m/s에서 조향 반응이 150 ms 늦으면 꺾기 전에 약 6.3 cm를 더 진행합니다. 같은 속도에서 관성 감속도가 0.55 m/s²에서 0.24 m/s²로 낮아지면, 지연을 제외한 정지거리는 약 16 cm에서 37 cm로 늘어납니다. 급한 코너의 경로와 속도를 함께 제한해야 하는 이유입니다. [Stanford 주행 가능 범위 연구](https://ddl.stanford.edu/sites/g/files/sbiybj25996/files/media/file/brown_safe_driving_envelopes_2016_0.pdf)

### 명령과 실측을 비교하는 제어

1. 동기화한 뒷차축 자세에서 최근 100 ms 이내 변위와 방향 변화를 사용해 속도와 회전율을 구합니다. 앞바퀴 각도 표본이 있으면 그 값을 사용합니다. 표본이 없으면 충분히 움직이는 조건에서 회전율과 속도로 차량이 실제로 그린 곡률을 구합니다.
2. 현재 바퀴 방향이 조향 지연 동안 유지돼도 앞범퍼와 차체에 여유가 있는지 확인합니다. 그 뒤 각 조향 후보에 대해 이전 명령, 현재 조향, 새 명령까지의 지연과 조향 변화율을 반영해 경로를 검사합니다.
3. 확인된 전진 거리 안에 정지할 수 있는지 실측 속도와 보수적인 감속도로 검사합니다. 정지거리에는 반응 시간 동안의 이동 거리와 `v²/(2a)`를 더합니다. 목표 속도에는 명령 경로와 실측 경로의 곡률 한계를 함께 적용합니다. [Regulated Pure Pursuit 논문](https://arxiv.org/abs/2305.20026)
4. 실측 속도, 목표 속도와 최근 가속을 비교해 제한된 범위에서 PWM을 조정합니다. 일정한 오차만 누적하며 PWM이 한계에 닿으면 더 밀어 올리지 않습니다. 속도가 목표보다 0.05 m/s 넘게 빠르면 모터 출력을 0으로 내려 관성 감속합니다. 전진 공간이 허용하는 동안 조향은 계속 제어합니다.
5. 구동 후 이동 없음, 조향 오차, 비정상 회전이나 측면 이동, 관성 감속 부족을 감시합니다. 이상을 감지하면 목표 속도를 0.15 m/s 이하로 낮추고 같은 이상이 4회 연속이면 정지합니다. 큰 과속, 예상치 못한 후진, 정지 여유 소실과 자세 데이터 단절에는 제어 세션을 중지합니다. 자세 입력이 없는 경우에는 기존 이동 불확실성 여유와 0.20 m/s 목표 상한을 사용합니다.

낮은 물체를 항상 검출하거나 센서와 구동기 고장을 소프트웨어만으로 복구할 수는 없습니다. 실제 한계를 확인하려면 배터리 상태와 노면을 바꿔 바퀴 조향각·속도·정지거리와 명령 로그를 함께 기록합니다. 이동 장애물의 속도 추정, 전원 상태 계측, 독립 충돌 센서와 정지 장치는 별도로 검증하는 항목입니다.

## 공개 구현과 비교한 시뮬레이션 개선 순서

1. **동일 조건에서 여러 번 비교합니다.** F1TENTH 벤치마크는 지도 기반, 지도 없는 반응형, 지역 지도 기반 등 여러 방식과 지도를 비교합니다. Gym JAX는 명시적 난수 키와 재현 가능한 물리 단계가 있습니다. 현재는 대형 트랙과 연속 직각 변형에 동일한 고장 일정과 여러 시드를 적용하고, 완주·충돌·벽 간격·대기·명령 여유를 함께 기록합니다. [F1TENTH Benchmarks](https://github.com/hawaii-nc/f1tenth_benchmarks) · [F1TENTH Gym JAX 문서](https://f1tenth-gym-jax.readthedocs.io/en/latest/index.html)
2. **주행 명령의 시간 예산을 맞춥니다.** 가상 완주 중에도 명령 유효시간이 부족한 구간을 찾습니다. 부족 구간은 Pi가 스캔을 받은 시각, 경로 계산 종료, Nano 응답을 같은 기록에서 확인해 실제 중단이 지연 때문인지 경로 길이 때문인지 구별합니다. 가상 지연 조건과 실제 기록으로 회귀 시험을 합니다.
3. **노면과 코너마다 감속 여유를 계획합니다.** TUM 속도 계산은 위치별 종·횡가속 한계와 곡률을 적용합니다. 현재 시뮬레이터에는 접지 제한을 같이 받는 간이 물리 모델을 추가했습니다. 실차의 직선·회전 감속을 측정한 뒤 그 한계를 속도 계획에도 적용하고 같은 조건에서 완주율과 랩타임을 비교합니다. [TUM 속도 계획 구현](https://github.com/TUMFTM/trajectory_planning_helpers/blob/master/trajectory_planning_helpers/calc_vel_profile.py)
4. **코너를 이루는 벽을 이어 경로를 만듭니다.** F1TENTH Local Maps는 관측 벽을 양쪽 경계로 짝지어 중심선과 폭을 계산합니다. 현재 여러 조향각의 차체 경로 비교를 기준선으로 두고, 짧은 지역 중심선을 따라 조향하는 후보를 추가해 연속 코너와 벽 가림에서 비교할 수 있습니다. 중심선 경로도 확인한 자유 공간과 정지거리로 검증합니다. [High-performance Racing on Unmapped Tracks using Local Maps](https://f1tenth.github.io/publications/Local_Maps.pdf)

## 안정적으로 빠르게 달리기 위한 다음 구조

1. **모르는 트랙에서는 지역 경로 계획과 독립 정지 감시를 함께 사용합니다.** 스캔을 점유·빈 공간·미관측으로 나누고, 자세 계측이 있으면 최근 스캔을 위치에 맞춰 겹칩니다. 조향 계획과 별도로 최신 스캔과 속도로 충돌이 임박했는지 판단하는 감시기를 둡니다. 현재 앞범퍼 및 차체 검사는 경로 계획 내부에 있습니다. [Nav2 Collision Monitor](https://github.com/ros-navigation/navigation2/tree/main/nav2_collision_monitor)
2. **보이는 거리에 따라 속도를 결정합니다.** 곡률 한계, 지연 후 멈출 수 있는 거리, 정보가 부족한 곳의 제한 속도 중 최솟값을 취합니다. 가까운 코너가 여러 개면 먼 코너에서부터 거꾸로 감속 가능한 속도를 계산하고, 현재 위치에서 앞으로 가속 가능한 속도를 계산해 더 낮은 값을 사용합니다. 속도에 맞춰 예측 거리를 바꾸며 아직 관측되지 않은 구간에서 속도를 올리지 않습니다. [Nav2 Regulated Pure Pursuit](https://github.com/ros-navigation/navigation2/tree/main/nav2_regulated_pure_pursuit_controller) · [F1TENTH 지역 지도 주행의 속도 계획](https://f1tenth.github.io/publications/Local_Maps.pdf)
3. **같은 트랙을 반복 주행할 때는 저속으로 경로를 기록한 뒤 최적화합니다.** 폐회로 중앙선 또는 주행선을 구하고 코너 전에 감속할 거리를 미리 계산합니다. 엔코더와 IMU로 현재 구간을 찾고 라이다로 가까운 장애물과 차체 여유를 계속 확인합니다. 잘 알려지지 않은 코너를 매 스캔에서 다시 추정하는 부담을 줄일 수 있습니다. [F1TENTH 주행 방식 비교](https://github.com/hawaii-nc/f1tenth_benchmarks) · [TUM 주행선 최적화](https://github.com/TUMFTM/global_racetrajectory_optimization)
4. **속도를 올릴 때는 주행 성공률과 처리 지연을 함께 봅니다.** 같은 구간을 반복해 충돌, 불필요한 정지, 잘못된 분기, 최소 벽 간격, 정지 요청 후 이동 거리, 랩타임, Pi에서 스캔부터 명령까지 걸리는 시간을 비교합니다. 벽 틈 길이, 시작 방향, 노면 접지, 센서 누락, 지연을 바꿔 반복합니다. 가상 성공 결과와 실차 결과를 따로 기록합니다.

현재는 **라이다 기반 지역 경로 평가 및 저신뢰 감속**까지 구현했습니다. 지도·위치 추정, 이동 장애물의 상대속도 계산, 독립 충돌 감시는 별도 설계입니다.
